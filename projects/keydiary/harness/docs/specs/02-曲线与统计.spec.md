# Spec: Phase 2 — 日记体验完善：曲线、统计与历史回顾

## Objective

将 Phase 1 的"实时热力图"升级为完整的"每日打字日记"页面——加入 KPM 时间曲线、今日之最统计卡片、应用分布饼图，并支持通过日历切换历史日期。

**目标用户**：已安装并使用数天的用户，想回顾和理解自己的打字行为。

**核心价值**：数据不再只是"当下的"，而是可以回顾的个人记录。

## Tech Stack（增量）

| 新增依赖 | 用途 |
|----------|------|
| `d3` (npm) | 图表渲染（面积图、环形图） |
| `cocoa` crate (Rust) | 获取当前前台应用名 |

## Commands

```bash
# 开发
npm run tauri dev

# 安装 D3
npm install d3 @types/d3

# 查询某天的 KPM 数据
sqlite3 ~/.keydiary/data.db "SELECT time_bucket, SUM(count)/5.0 as kpm FROM key_events WHERE date='2026-05-25' GROUP BY time_bucket ORDER BY time_bucket;"
```

## Functional Specifications

### FS-2.1 前台应用名采集

**描述**：在每次 keyDown 事件时，附带记录当前前台应用名，用于应用分布分析。

**采集实现**：
- macOS API：`NSWorkspace.shared.frontmostApplication.localizedName`
- 缓存策略：同一 5 秒窗口内不重复查询系统 API
- 写入 Aggregator 的 app_usage 维度

**新增数据库表 `app_usage`**：

| 列名 | 类型 | 约束 | 说明 |
|------|------|------|------|
| id | INTEGER | PK AUTOINCREMENT | 主键 |
| date | TEXT | NOT NULL | 日期 |
| time_bucket | TEXT | NOT NULL | 时间桶 |
| app_name | TEXT | NOT NULL | 应用名如 'Visual Studio Code' |
| key_count | INTEGER | NOT NULL DEFAULT 0 | 该桶内在此 app 中的击键数 |

唯一约束：`UNIQUE(date, time_bucket, app_name)`

索引：`idx_app_usage_date(date)`

**验收条件**：
- 数据库中 `app_usage` 表正确记录了应用名
- 在不同应用间切换打字，各应用的 key_count 独立累计

### FS-2.2 KPM 时间曲线

**描述**：以面积图展示全天的 KPM 变化节奏，X 轴为时间，Y 轴为 KPM 值。

**数据查询**：

```sql
SELECT time_bucket, CAST(SUM(count) AS REAL) / 5 as kpm
FROM key_events WHERE date = ?
GROUP BY time_bucket ORDER BY time_bucket;
```

**Tauri Command**：

```
Command: get_kpm_timeline
参数：{ date: String }
返回：Vec<{ time: String, kpm: f64 }>
```

**渲染规格**：
- 图表类型：D3.js 面积图（area chart）
- X 轴范围：00:00 → 23:55（每 5 分钟一个潜在数据点）
- Y 轴范围：0 → max(kpm) × 1.1
- 曲线插值：`d3.curveMonotoneX`（平滑自然）
- 填充色：半透明蓝色 `rgba(99, 179, 237, 0.3)`
- 描边色：`#4299e1`，2px
- Hover 交互：显示具体时间点的 KPM 值（tooltip）
- 参考线：个人日均 KPM 水平虚线

**视觉风格**：类似 Apple Watch 心率曲线，平滑过渡，有呼吸感。

**验收条件**：
- KPM 曲线正确反映全天打字节奏（高峰/低谷清晰可辨）
- 无数据的时间段不显示（曲线断开或归零）
- Hover tooltip 显示正确的时间和 KPM 值

### FS-2.3 今日之最统计卡片

**描述**：5 张卡片展示当日的关键指标，用趣味表达增加可读性。

**Tauri Command**：

```
Command: get_daily_highlights
参数：{ date: String }
返回：DailyHighlights {
    total_keystrokes: u64,
    peak_kpm: u32,
    active_minutes: u32,
    top_keys: Vec<{key: String, count: u32}>,  // Top 5
    longest_flow: { start: String, end: String, minutes: u32 },
    undo_count: u32,       // Cmd+Z 次数
    backspace_count: u32,  // Delete 键次数
}
```

**卡片内容**：

| 卡片 | 主数字 | 辅助文案 |
|------|--------|----------|
| 总击键 | 12,847 | ≈ {N} 页 A4（每页 2500 字符） |
| 峰值 KPM | 127 | "你最快的 1 分钟" |
| 活跃时间 | 3h 45m | "有击键的时段总长" |
| 最长心流 | 43 min | "14:05-14:48 连续打字" |
| 后悔指数 | ↩ 87 次 | "⌫ 1,203 次" |

**心流定义**：连续有数据的时间桶（相邻桶间隔 ≤ 5 分钟即视为连续）。

**验收条件**：
- 5 张统计卡片数据正确
- 趣味文案计算正确（不出现"0 页""NaN"）
- 无数据时显示默认状态（如 "—" 或 "暂无数据"）

### FS-2.4 应用分布饼图

**描述**：环形图展示当日击键在各应用中的分布。

**Tauri Command**：

```
Command: get_app_distribution
参数：{ date: String }
返回：Vec<{ app_name: String, count: u64, percentage: f64 }>
（取 Top 8，超出的归入"其他"）
```

**渲染规格**：
- 图表类型：D3.js donut chart（环形图）
- 颜色映射：固定映射常用应用（VSCode=蓝, Chrome=红, Terminal=绿, Slack=紫, 其他=灰）
- 中心文字：总击键数
- Hover 交互：显示应用名 + 击键数 + 百分比
- 右侧图例：应用名 + 颜色色块 + 百分比

**验收条件**：
- 饼图能区分出主要应用（VSCode / Chrome / Terminal 等）
- 各扇区百分比之和 = 100%
- 少于 2 个应用时仍然正确渲染

### FS-2.5 日历导航

**描述**：月历视图，允许用户切换到任意有数据的历史日期。

**交互设计**：
- 入口：页面右上角日历图标 📅，点击展开日历面板
- 布局：标准月历网格（周一起始）
- 月份切换：左右箭头切换月份
- "今天"按钮：快速回到当日

**日期状态**：

| 状态 | 视觉表现 | 行为 |
|------|----------|------|
| 有数据 | 正常颜色，可点击 | 切换日记到该日 |
| 无数据 | 灰色 | 不可点击 |
| 当前选中 | 高亮圆圈 | — |
| 今天 | 特殊标记（如下划线） | — |

**数据预加载**：
- 月份切换时查询 `SELECT DISTINCT date FROM daily_summary WHERE date BETWEEN ? AND ?`
- 缓存已查询月份的数据状态

**切换行为**：
- 点击有数据的日期 → 页面内所有图表/卡片切换到对应日期
- 数据加载中显示 loading 状态
- 加载失败显示错误提示

**验收条件**：
- 点击历史日期，所有图表切换到对应数据
- 无数据日期灰色不可点击
- 点击"今天"回到当日
- 月份切换流畅，无明显延迟

### FS-2.6 daily_summary 自动更新

**描述**：每次 Aggregator flush 时，同步更新 `daily_summary` 表的聚合数据。

**更新逻辑**：
- 触发时机：每次 flush 后
- 计算字段：total_keystrokes、active_minutes、peak_kpm
- 使用 `INSERT OR REPLACE` 语义

**验收条件**：
- `daily_summary` 数据与 `key_events` 聚合结果一致
- 页面查询 daily_summary 时响应 < 10ms

## Non-Functional Requirements

| 指标 | 目标值 |
|------|--------|
| 页面完整加载（含所有查询和渲染） | < 500ms |
| 日期切换到数据展示 | < 300ms |
| D3 图表渲染 | < 100ms |
| daily_summary 查询 | < 10ms |

## Boundaries

**Always**：
- 日历切换时所有图表同步更新（不出现数据不一致）
- 无数据时优雅降级（显示占位符，不报错）

**Ask First**：
- 修改 KPM 计算公式
- 调整时间桶粒度
- 新增数据维度采集

**Never**：
- 不在前端做复杂数据聚合（所有聚合在 Rust/SQL 侧完成）
- 不缓存过期数据（当日数据始终从 Rust 侧获取最新）

## Success Criteria

- [ ] 主窗口展示完整日记页面（热力图 + 曲线 + 统计 + 饼图）
- [ ] KPM 曲线正确反映全天打字节奏
- [ ] 5 张统计卡片数据正确
- [ ] 应用分布饼图能区分出主要应用
- [ ] 点击日历中的历史日期，所有图表切换到对应数据
- [ ] 无数据日期灰色不可点击
- [ ] 点击"今天"按钮回到当日
- [ ] 页面加载速度 < 500ms
- [ ] app_usage 表正确记录了应用名

## Dependencies

- 前置依赖：Phase 1（按键采集 + 热力图 + SQLite 数据）
