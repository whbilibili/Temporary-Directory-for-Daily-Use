# Spec: Phase 4 — 精细化打磨：成就系统、多主题与高级设置

## Objective

为产品增加"可玩性"（成就系统）和"个性化"（多主题），并完善用户控制能力（高级设置），使产品从"能用"进化到"好用且有粘性"。

**目标用户**：已持续使用一周以上的活跃用户。

**核心价值**：通过成就激励留存，通过个性化增强归属感，通过设置赋予控制权。

## Tech Stack（增量）

| 新增依赖 | 用途 |
|----------|------|
| `auto-launch` crate | 开机自启管理 |
| `svelte/transition` | 成就解锁动画 |
| CSS Custom Properties | 主题系统 |

```bash
# 开发

## Functional Specifications

### FS-4.1 成就系统 — 数据模型

**描述**：8 个基础成就，纯数据驱动判定，无需额外采集。

**设计原则**：
- 无压力：不设期限，不施加压力，是"发现彩蛋"而非"每日任务"
- 数据驱动：所有判定基于已有数据的聚合查询
- 低频惊喜：不是每天都能解锁，但解锁时有仪式感

**成就列表**：

| ID | 名称 | 图标 | 解锁条件 | 分类 |
|----|------|------|----------|------|
| `first_day` | 初次记录 | 种子 | 首次完成一天的数据采集 | 里程碑 |
| `10k_club` | 万键俱乐部 | 键盘 | 单日击键突破 10,000 次 | 里程碑 |
| `100k_club` | 十万大关 | 山峰 | 单日击键突破 100,000 次 | 里程碑 |
| `flow_master` | 心流大师 | 冥想 | 连续 7 天每天心流 > 30 分钟 | 习惯 |
| `vim_disciple` | Vim 信徒 | 忍者 | 累计 hjkl 使用次数超过方向键 | 技能 |
| `shortcut_ninja` | 快捷键忍者 | 闪电 | 单日快捷键组合使用 > 300 次 | 技能 |
| `night_owl` | 夜猫子 | 猫头鹰 | 凌晨 0:00-4:00 击键 > 1000（连续 3 天） | 生活 |
| `steady_hand` | 稳定输出 | 图表 | 连续 14 天日击键波动 < 25% | 习惯 |

**数据库表 `achievements`**：

| 列名 | 类型 | 约束 | 说明 |
|------|------|------|------|
| id | TEXT | PK | 成就 ID 如 'flow_master' |
| unlocked_at | TEXT | NULLABLE | 解锁时间或 NULL |
| progress | REAL | NOT NULL DEFAULT 0 | 进度 0.0-1.0 |
| notified | INTEGER | NOT NULL DEFAULT 0 | 是否已通知用户 |

**初始化**：App 首次启动时插入所有 8 条成就记录（未解锁状态）。

**验收条件**：
- achievements 表包含 8 条初始记录
- 进度字段正确反映当前状态

### FS-4.2 成就判定引擎

**描述**：每次 Aggregator flush 时异步检查成就条件。

**触发时机**：每 60 秒（随 Aggregator flush）

**判定逻辑**（伪代码）：

| 成就 | 查询逻辑 |
|------|----------|
| `first_day` | 今日有任何数据 |
| `10k_club` | 今日 total_keystrokes >= 10000 |
| `100k_club` | 今日 total_keystrokes >= 100000 |
| `flow_master` | 查询最近连续 N 天是否每天都有 >= 30 分钟心流 |
| `vim_disciple` | 累计 hjkl(keycode 4,38,40,37) 总数 > 方向键(123-126) 总数 |
| `shortcut_ninja` | 今日含修饰键的组合按键 > 300 |
| `night_owl` | 最近 3 天凌晨 00:00-04:00 各有 > 1000 击键 |
| `steady_hand` | 最近 14 天的日击键数标准差/均值 < 0.25 |

**进度更新**：对于渐进式成就，每次检查时更新 progress 字段（如 flow_master 3/7 = 0.43）。

**验收条件**：
- 连续使用 1 天后自动解锁 "初次记录"
- 进度字段随实际数据变化而更新
- 不重复解锁已解锁的成就

### FS-4.3 成就解锁动画

**描述**：成就解锁时前端播放全屏庆祝动画。

**触发机制**：
- Rust 侧检测到新解锁 -> `app.emit("achievement_unlocked", payload)`
- 前端监听事件 -> 触发 overlay 动画

**动画规格**：
- 时长：2-3 秒
- 内容：成就图标从中心放大弹入 + 名称 + "已解锁！"文字渐入
- 交互：自动消失或点击关闭
- 层级：全屏 overlay，覆盖所有内容

**验收条件**：
- 成就解锁时有全屏动画弹出
- 动画流畅无卡顿
- 多个成就同时解锁时依次播放

### FS-4.4 成就展示页面

**描述**：主窗口新增成就 Tab，展示所有成就的状态。

**Tab 导航扩展**：

```
[ 日记 ]  [ 周报 ]  [ 成就 ]
```

**展示规则**：

| 状态 | 视觉 |
|------|------|
| 已解锁 | 全彩图标 + 名称 + 解锁日期 |
| 未解锁 | 灰色图标 + 名称 + 进度条 |
| 未解锁（进度中） | 灰色图标 + "3/7 天" 进度文字 |

**Hover/点击**：显示解锁条件说明文字。

**验收条件**：
- 成就页面显示所有 8 个成就的状态
- 已解锁的显示解锁日期
- 未解锁的显示进度

### FS-4.5 视觉主题系统

**描述**：4 套内置主题，通过 CSS 变量实现全局换肤。

**主题定义**（每套主题的色彩变量）：

| 变量 | 用途 |
|------|------|
| --color-background | 页面背景 |
| --color-surface | 卡片/容器背景 |
| --color-text | 主文字 |
| --color-text-secondary | 辅助文字 |
| --color-border | 边框 |
| --color-heatmap-cold | 热力图最低频 |
| --color-heatmap-warm | 热力图中频 |
| --color-heatmap-hot | 热力图最高频 |
| --color-accent | 强调色 |
| --color-chart-line | 图表线条 |
| --color-chart-fill | 图表填充 |

**4 套主题**：

| ID | 名称 | 风格描述 |
|----|------|----------|
| cyberpunk | 赛博朋克 | 深色底 + 霓虹色热力（默认） |
| minimal | 极简黑白 | 灰度热力图，专注内容 |
| nature | 自然渐变 | 蓝绿色系，护眼舒适 |
| retro | 复古终端 | 黑底绿字 CRT 风格 |

**切换机制**：
- 设置页面选择主题
- 立即生效（通过修改 `document.documentElement` 的 CSS 变量）
- 选择持久化到 settings 表

**热力图色谱适配**：
- 使用主题的 heatmapCold/Warm/Hot 三色做三段插值
- intensity < 0.5: Cold -> Warm 线性插值
- intensity >= 0.5: Warm -> Hot 线性插值

**验收条件**：
- 切换主题后热力图、曲线、卡片配色全部跟随变化
- 4 套主题视觉各有特色，无明显 UI bug
- 主题选择重启后保持

### FS-4.6 高级设置面板

**描述**：提供用户可控的设置项，存储在 SQLite settings 表中。

**数据库表 `settings`**：

| 列名 | 类型 | 约束 | 说明 |
|------|------|------|------|
| key | TEXT | PK | 设置键名 |
| value | TEXT | NOT NULL | 设置值（JSON 字符串） |

**设置项**：

| 设置项 | key | 类型 | 默认值 | 说明 |
|--------|-----|------|--------|------|
| 视觉主题 | theme | 选择器 | "cyberpunk" | 4 选 1 |
| 键盘布局 | keyboard_layout | 选择器 | "qwerty" | QWERTY/Colemak/Dvorak |
| 排除应用 | excluded_apps | 列表 | "[]" | 在这些 app 中暂停采集 |
| 工作时段 | work_hours_enabled | 开关 | "false" | 是否仅在设定时段采集 |
| 工作时段起始 | work_hours_start | 时间 | "00:00" | |
| 工作时段结束 | work_hours_end | 时间 | "23:59" | |
| 开机自启 | auto_start | 开关 | "false" | 是否随系统启动 |

**Tauri Commands**：

| Command | 参数 | 返回 |
|---------|------|------|
| `get_settings` | 无 | `HashMap<String, String>` |
| `update_setting` | `{ key, value }` | `Result<(), String>` |
| `get_installed_apps` | 无 | `Vec<String>`（已安装应用列表） |

**验收条件**：
- 所有设置项可正常修改并持久化
- 重启 app 后设置保持

### FS-4.7 排除应用功能

**描述**：在指定应用中暂停按键采集。

**实现逻辑**：
- 采集回调中检查当前前台应用是否在排除列表中
- 命中则跳过记录

**设置 UI**：
- 列出当前系统已安装的应用（复选框列表）
- 支持搜索/过滤
- 勾选 = 排除

**验收条件**：
- 在排除应用中打字时击键数不增长
- 切回非排除应用后恢复采集
- 排除列表修改立即生效

**Tauri Command**：

| Command | 参数 | 返回 |
|---------|------|------|
| `export_data` | `{ format: "json"/"csv", date_range?: { start, end } }` | `Result<String, String>` |

**JSON 导出结构**：

  "app_version": "1.0.0",

      "apps": [{ "app": "VSCode", "count": 8234 }],

```

**验收条件**：
- 导出的 JSON 内容完整可读
- CSV 格式可被 Excel 正确打开
- 支持按日期范围筛选导出

### FS-4.9 键盘布局切换

**描述**：支持 3 种键盘布局的热力图渲染。

**预置布局**：

| ID | 名称 | 说明 |
|----|------|------|
| qwerty | QWERTY | 标准布局（默认） |
| colemak | Colemak | 优化布局 |
| dvorak | Dvorak | 替代布局 |

**切换影响**：
- 热力图的键位坐标重新排列
- keycode -> label 映射根据布局变化
- 物理键码不变（数据层不受影响）

**验收条件**：
- 切换布局后热力图键位标签正确
- 数据不丢失（只是渲染变化）

### FS-4.10 开机自启

**描述**：支持设置 app 随系统启动。

**实现**：使用 `auto-launch` crate 的 macOS Login Items 机制。

**验收条件**：
- 开启后重启系统，app 自动启动
- 关闭后重启系统，app 不自动启动

## Non-Functional Requirements

| 指标 | 目标值 |
|------|--------|
| 成就判定延迟 | < 100ms（不阻塞 flush） |
| 主题切换响应 | < 50ms（即时生效） |
| 设置保存延迟 | < 50ms |
| 数据导出（1 年数据） | < 5s |

## Boundaries

**Always**：
- 成就判定只读已有数据，不引入额外采集
- 主题变化不影响数据层
- 危险操作（清除数据）需二次确认

**Ask First**：
- 新增成就
- 新增主题
- 修改成就解锁条件

**Never**：
- 不自动清除用户数据
- 不向外部发送成就/设置数据
- 不限制用户导出自己的数据
