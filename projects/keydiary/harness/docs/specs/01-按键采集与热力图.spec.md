# Spec: Phase 1 — 最小核心功能：按键采集与热力图

## Objective

实现按键事件的静默采集、本地存储，并在前端渲染实时更新的键盘热力图。这是产品的核心验证点——证明"按键可视化"这个概念有吸引力。

**目标用户**：Mac 用户（开发者、写作者、重度键盘使用者）

**核心价值**：将无形的键盘使用行为转化为直观的视觉数据。

## Tech Stack（增量）

| 新增依赖 | 用途 |
|----------|------|
| `core-graphics` crate | macOS CGEventTap 按键监听 |

## Functional Specifications

### FS-1.1 macOS Accessibility 权限引导

**描述**：按键监听需要 Accessibility 权限，应用需引导用户完成授权。

**权限检测逻辑**：

1. App 启动时调用 `AXIsProcessTrusted()` 检测权限状态
2. 未授权 -> 前端显示引导页面
3. 已授权 -> 直接开始采集

**引导页面内容**：

- 说明文字：解释为什么需要此权限（只统计频率，不记录内容）
- 操作指引：带截图的步骤说明
- 按钮："打开系统设置" -> 跳转到辅助功能权限页面
- 后台轮询：每 2 秒检测权限状态，授权后自动切换到主界面

**Tauri Commands**：

| Command | 参数 | 返回 |
|---------|------|------|
| `check_accessibility_permission` | 无 | `bool` |
| `open_accessibility_settings` | 无 | `void` |

**验收条件**：

- 未授权时显示引导页面
- 点击按钮能跳转到系统设置对应页面
- 授权后页面自动切换到主界面（无需重启 app）

### FS-1.2 按键采集引擎

**描述**：使用 macOS CGEventTap 监听全局按键事件，仅捕获 keyDown 事件的物理键码。

**架构**：

```
CGEventTap (系统级监听)
    | keyDown 事件回调 (key_code, timestamp)
    v
Aggregator (内存聚合器)
    | 每 60 秒 batch flush
    v
SQLite (持久化)
```

**CGEventTap 配置**：

- 位置：`CGEventTapLocation::Session`
- 模式：`CGEventTapOptions::ListenOnly`（只监听，不拦截/修改事件）
- 事件类型：仅 `CGEventType::KeyDown`
- 运行环境：独立线程 + `CFRunLoop::run_current()`

**隐私安全约束（硬性）**：

- 不记录按键的时序序列（无法还原输入内容）
- 不记录精确时间戳（只聚合到 5 分钟桶）
- SecureInput 模式下跳过采集（密码输入框）
- 不做任何网络通信

**SecureInput 检测**：

- 每次 keyDown 回调中调用 `CGSIsSecureEventInputSet()`
- 返回 true 时丢弃该事件，不计数

**验收条件**：

- 授权后按键采集自动开始
- CPU 占用 < 1%（Activity Monitor 观察 5 分钟）
- 内存占用 < 50MB
- 密码输入框中打字时不被记录

### FS-1.3 内存聚合器 (Aggregator)

**描述**：在内存中聚合按键数据，定期批量写入 SQLite，减少磁盘 IO。

**数据结构**：

```
buffer: HashMap<(date: String, time_bucket: String, key_code: u16), count: u32>
```

**聚合规则**：

- 时间桶粒度：5 分钟（对齐到 0/5/10/15/20/25/30/35/40/45/50/55 分）
- 刷新频率：每 60 秒或 buffer 达到 1000 条记录时触发 flush
- 线程安全：`Arc<Mutex<Aggregator>>`

**Flush 行为**：

- 使用 UPSERT 语义：`INSERT ... ON CONFLICT DO UPDATE SET count = count + excluded.count`
- flush 完成后清空 buffer
- flush 失败时保留 buffer 数据，下次重试

**验收条件**：

- 正常打字 1 分钟后，SQLite 中有数据（flush 生效）
- 退出 app 前执行一次最终 flush（不丢数据）
- 重启 app 后历史数据仍在

### FS-1.4 数据库 Schema

**表 `key_events`**：

| 列名 | 类型 | 约束 | 说明 |
|------|------|------|------|
| id | INTEGER | PK AUTOINCREMENT | 主键 |
| date | TEXT | NOT NULL | 日期 'YYYY-MM-DD' |
| time_bucket | TEXT | NOT NULL | 时间桶 'HH:MM'（5 分钟粒度） |
| key_code | INTEGER | NOT NULL | macOS virtual keycode |
| key_label | TEXT | NOT NULL | 可读标签如 'A', 'Space', 'Cmd' |
| count | INTEGER | NOT NULL DEFAULT 0 | 该桶内按下次数 |
| created_at | TEXT | DEFAULT datetime('now','localtime') | 创建时间 |

唯一约束：`UNIQUE(date, time_bucket, key_code)`

索引：`idx_key_events_date(date)`, `idx_key_events_date_key(date, key_code)`

**表 `daily_summary`**：

| 列名 | 类型 | 约束 | 说明 |
|------|------|------|------|
| date | TEXT | PK | 日期 |
| total_keystrokes | INTEGER | NOT NULL DEFAULT 0 | 当日总击键数 |
| active_minutes | INTEGER | NOT NULL DEFAULT 0 | 有击键的桶数 x 5 |
| peak_kpm | INTEGER | NOT NULL DEFAULT 0 | 最高每分钟击键数 |
| updated_at | TEXT | DEFAULT datetime('now','localtime') | 最后更新时间 |

**验收条件**：

- App 启动时自动建表（不存在则创建）
- 数据插入和查询性能满足实时要求

### FS-1.5 keycode 到 label 映射

**描述**：将 macOS virtual keycode 转换为人类可读的标签。

**映射范围**（约 60-80 个键）：

- 字母键：A-Z（keycode 0-50 范围内的字母）
- 数字键：0-9
- 修饰键：Cmd(55), Shift(56), Option(58), Ctrl(59), CapsLock(57)
- 功能键：F1-F12, Esc(53), Tab(48), Space(49), Return(36), Delete(51)
- 方向键：Left(123), Right(124), Down(125), Up(126)
- 符号键：常用标点符号
- 未知键码：返回 "?"

**验收条件**：

- 热力图上每个键显示正确的标签文字
- 无常用键显示为 "?"

### FS-1.6 键盘热力图渲染

**描述**：在前端以 SVG 渲染标准 QWERTY 键盘布局，根据按键频率着色。

**布局数据**：

- QWERTY 标准布局，约 60-80 个键
- 每个键定义：`{ code, label, x, y, width, height }`（归一化坐标 0-1）
- 支持 5 行：数字行、QWERTY 行、ASDF 行、ZXCV 行、修饰键行

**渲染规格**：

- 容器：`<svg viewBox="0 0 1000 400">`
- 每个键：圆角矩形 + 居中文字
- 圆角半径：6px
- 键间距：4px
- 描边：`#333`，1px

**色彩映射**：

- 输入：每个键的按压次数 / 最大按压次数 = intensity (0-1)
- 输出：HSL 色相从 240 度(蓝/冷) 到 0 度(红/热)
- 公式：`hsl(240 - intensity * 240, 80%, 50% + (1 - intensity) * 30%)`
- 无按键记录的键：保持底色

**刷新策略**：

- 每 10 秒向 Rust 侧查询最新数据并重新渲染
- 不使用 WebSocket，使用定时轮询 invoke

**Tauri Command**：

| Command | 参数 | 返回 |
|---------|------|------|
| `get_today_heatmap` | 无 | `Vec<{key_code, key_label, total}>` |

**验收条件**：

- 正常打字 1 分钟后打开主窗口能看到热力图
- 常用键（Space, E, T）颜色明显偏暖
- 热力图每 10 秒自动刷新

### FS-1.7 实时统计面板

**描述**：主页面底部展示三个实时数据卡片。

**数据卡片**：

| 卡片 | 数据来源 | 刷新频率 |
|------|----------|----------|
| 今日击键 | `get_today_total` Command | 10 秒 |
| 当前 KPM | Tauri Event `kpm_update` | 1 秒 |
| 运行时长 | 前端计时器 | 1 秒 |

**KPM 计算逻辑**（Rust 侧）：

- 维护最近 60 秒的击键计数滑动窗口
- 每秒通过 `app.emit("kpm_update", { kpm })` 推送给前端

**Tauri Command**：

| Command | 参数 | 返回 |
|---------|------|------|
| `get_today_total` | 无 | `u64` |

**验收条件**：

- 今日击键总数实时递增
- 当前 KPM 数字每秒更新
- KPM 在停止打字后逐渐降为 0

### FS-1.8 采集状态指示

**描述**：在主页面底部显示采集器的当前状态。

**状态枚举**：

| 状态 | 显示 | 触发条件 |
|------|------|----------|
| running | 绿色圆点 + "采集中" | 正常运行 |
| paused | 黄色圆点 + "已暂停" | 用户手动暂停 |
| no_permission | 红色圆点 + "未授权" | Accessibility 权限缺失 |

**Tauri Command**：

| Command | 参数 | 返回 |
|---------|------|------|
| `get_collector_status` | 无 | `{ status: "running" / "paused" / "no_permission" }` |

**验收条件**：

- 正常运行时显示绿色"采集中"
- 权限被撤销时自动切换到红色"未授权"

## Non-Functional Requirements

| 指标 | 目标值 |
|------|--------|
| CPU 占用（采集运行时） | < 1% |
| 内存占用 | < 50MB |
| 页面加载到渲染完成 | < 500ms |
| 数据写入延迟 | < 60s（flush 周期） |
| 退出时数据丢失 | 0（退出前强制 flush） |

## Boundaries

**Always**：

- SecureInput 激活时停止采集
- 退出前 flush 所有 buffer 数据
- 日志记录异常但不中断运行

**Ask First**：

- 修改聚合粒度（当前 5 分钟桶）
- 调整 flush 频率

**Never**：

- 记录按键序列或时间戳精确序列
- 进行任何网络通信
- 在 SecureInput 模式下记录任何数据
- 修改或拦截系统事件（只 Listen）
