## 错误→规则固化案例

### 案例 1：repo cat 挂死

**错误**：Agent 调用 repo cat 读取大文件，导致整个系统卡死 30s

**识别模式**：
- 条件：需要读取文件内容
- 错误：工具选择错误

**固化规则**：
- 禁止使用 repo cat
- 改用 mtcurl REST API

**写入位置**：
- SOUL.md（工具禁令）
- AGENTS.md（工具禁令表）
- MEMORY.md（工具踩坑经验）

**下次遇到**：自动触发规则，不再犯错

### 案例 2：并行下载卡死

**错误**：Agent 使用 `& wait` 并行下载多个文件，mtcurl 挂起时整个 exec 永久卡死

**识别模式**：
- 条件：同时下载多个文件
- 错误：并发策略错误

**固化规则**：
- 禁止使用 `& wait` 并行
- 改用串行逐个 + timeout=30

**写入位置**：
- SOUL.md（工具禁令）
- AGENTS.md（工具禁令表）
- MEMORY.md（工具踩坑经验）

**下次遇到**：自动触发规则，不再犯错

### 案例 3：金额精度错误

**错误**：Agent 使用 float 计算金额，导致精度错误（99.99 + 13% = 112.9887，四舍五入后变成 112.99）

**识别模式**：
- 条件：金额计算
- 错误：数据类型选择错误

**固化规则**：
- 所有金额必须使用 Decimal 或 BigInt
- 数据库存储为 NUMERIC(18,2)
- 所有计算必须经过单测

**写入位置**：
- SOUL.md（核心原则）
- MEMORY.md（业务规则）
- USER.md（常见问题）

**下次遇到**：自动触发规则，不再犯错

## 学习收获

### 驾驭工程的核心价值

1. **系统化地把错误变成免疫力**
   - 不是靠 Agent 的"判断力"避免错误
   - 而是硬编码禁止 + 规则固化

2. **证伪优先对抗确认偏误**
   - LLM 天然有确认偏误
   - 强制先找反证是工程手段

3. **知识写入门控避免腐烂**
   - 不是什么知识都写入
   - importance >= 0.88 才写入

4. **错误→规则固化流程是闭环**
   - 犯错 → 识别模式 → 固化规则 → 回测验证 → 规则生效
   - 每一次错误都成为系统的免疫力
