## 1. 产品概述

### 1.1 产品背景

家庭日常生活中，食品、日用品、药品等物品种类繁多，库存状态难以追踪，常常出现"买重了"或"用完了才发现"的情况。现有的购物清单工具只解决了"买什么"的问题，却没有解决"家里还有多少"的问题。

本产品旨在为家庭提供一套完整的物品库存管理解决方案，覆盖从入库、消耗、预警到补购的完整闭环。

### 1.2 产品目标

- **核心目标**：帮助家庭成员随时掌握家中物品的库存状态，避免缺货或过度囤积。
- **次要目标**：通过购物清单和预算统计，辅助家庭合理规划采购支出。
- **长期目标**：通过消耗数据积累，实现智能补货预测，降低家庭管理成本。

### 1.3 产品定位

| 维度 | 描述 |
|------|------|
| 目标用户 | 有家庭的成年人，关注家庭物品管理效率 |
| 使用场景 | 日常查看库存、生成购物清单、控制家庭开支 |
| 使用频率 | 每周 1～3 次 |
| 平台 | Web 端（优先），后续支持 PWA 移动端 |

### 1.4 产品范围

**本期包含**：物品管理、库存管理、警告提醒、购物清单、保质期追踪、位置追踪、家庭共享、预算统计、定期重复购买。

**本期不包含**：条码扫描、AI 图像识别、第三方电商对接、财务报表导出。

## 2. 用户分析

### 2.1 用户角色

#### 角色一：家庭管理者（主要用户）
- **典型画像**：25～45 岁，负责家庭日常采购的成员（通常是家中主要负责人）
- **核心诉求**：随时知道家里缺什么、快速生成购物清单、控制月度开支
- **痛点**：去超市前不知道买什么、买回来发现已经有了、食品过期浪费

#### 角色二：家庭成员（协作用户）
- **典型画像**：同住的其他家庭成员（配偶、父母等）
- **核心诉求**：查看当前库存、知道某样东西放在哪里
- **痛点**：找不到东西、不知道还有没有存货

### 2.2 用户故事

| # | 作为… | 我想… | 以便… |
|---|-------|-------|-------|
| U1 | 家庭管理者 | 查看所有物品的当前库存数量 | 随时掌握家中存货状态 |
| U2 | 家庭管理者 | 设置每种物品的库存警告线 | 在物品不足时及时收到提醒 |
| U3 | 家庭管理者 | 一键生成购物清单 | 快速整理需要补购的物品 |
| U4 | 家庭管理者 | 查看本月家庭采购支出 | 控制家庭开支在预算范围内 |
| U5 | 家庭管理者 | 追踪食品和药品的保质期 | 避免过期浪费或误食过期食品 |
| U6 | 家庭管理者 | 记录物品的存放位置 | 快速找到需要的物品 |
| U7 | 家庭管理者 | 设置定期重复购买的物品 | 不会忘记定期补充的日常用品 |
| U8 | 家庭成员 | 查看实时库存 | 了解家中物品存量，避免重复购买 |
| U9 | 家庭成员 | 向购物清单中添加物品 | 告知家庭管理者需要补充的物品 |

### 2.3 使用场景

**场景一：周末采购前**
> 家庭管理者打开应用，查看库存警告列表，确认哪些物品需要补充，一键生成购物清单，带着清单去超市。

**场景二：日常消耗记录**
> 用完一瓶洗发水，打开应用将库存数量减少，系统自动检测是否低于警告线，若低于则加入待购清单。

**场景三：食品过期预警**
> 系统在食品保质期前 7 天推送提醒，家庭管理者查看后决定尽快使用或丢弃。

**场景四：家庭成员查找物品**
> 家庭成员想找创可贴，打开应用搜索，看到存放位置为"卫生间柜子第二层"，直接找到。

## 4. 功能详细说明

### 4.1 物品管理

#### 功能描述
物品是系统的基础数据单元，支持对家中所有物品进行统一录入和管理。

#### 数据模型

| 字段 | 类型 | 必填 | 说明 |
|------|------|------|------|
| 物品名称 | 文本 | 是 | 如"东北大米" |
| 分类 | 单选 | 是 | 食品/日用品/药品/家电/其他 |
| 分组 | 单选 | 否 | 用户自定义分组，如"厨房用品" |
| 标签 | 多选 | 否 | 用户自定义标签，如"有机""进口" |
| 单位 | 文本 | 是 | 如"袋""瓶""个""kg" |
| 备注 | 文本 | 否 | 品牌、规格等补充信息 |
| 图片 | 图片 | 否 | 物品照片，便于识别 |

#### 功能点

**物品录入**
- 支持手动填写物品信息
- 支持从"常用物品库"快速选择预设物品（系统内置常见家用物品）
- 支持批量导入（CSV 格式）

**分类与分组**
- 系统预设一级分类：食品、日用品、药品、家电、其他
- 用户可自定义二级分组（如"厨房""卫生间""客厅"）
- 标签支持自由创建，一个物品可打多个标签

**搜索与筛选**
- 支持按名称关键词搜索
- 支持按分类、分组、标签筛选
- 支持按库存状态筛选（正常/警告/缺货）

**物品编辑与删除**
- 支持修改物品的所有字段
- 删除物品时，若该物品有库存记录，需二次确认
- 支持软删除（归档），归档物品不显示在主列表但保留历史数据

#### 业务流程

```
用户点击"添加物品"
  → 选择录入方式（手动 / 从常用库选择）
  → 填写物品信息（名称、分类、单位等）
  → 设置初始库存数量
  → 保存 → 物品出现在库存列表
```

### 4.2 库存管理

#### 功能描述
记录每种物品的当前库存数量，支持快速增减操作，并保留完整的修改历史。

#### 数据模型

| 字段 | 类型 | 说明 |
|------|------|------|
| 当前数量 | 数字 | 当前库存量 |
| 单位 | 文本 | 继承自物品设置 |
| 警告线 | 数字 | 低于此值触发提醒 |
| 最后更新时间 | 时间 | 最近一次修改的时间 |
| 最后更新人 | 用户 | 最近一次修改的家庭成员 |

#### 功能点

**库存查看**
- 主页以卡片或列表形式展示所有物品的当前库存
- 库存状态用颜色区分：绿色（充足）、黄色（警告）、红色（缺货/为零）
- 支持按状态排序，警告和缺货物品置顶

**快速增减**
- 在列表页直接点击 +/- 按钮调整数量，无需进入详情页
- 支持直接输入数字修改数量
- 每次修改自动记录操作人和时间

**修改历史**
- 每条库存变更记录包含：操作人、变更前数量、变更后数量、时间、备注
- 历史记录保留最近 90 天
- 支持撤销最近一次操作（仅限 5 分钟内）

**冲突处理**
- 多人同时修改同一物品时，采用"最后写入生效"策略
- 系统在修改历史中保留所有操作记录，便于追溯

#### 业务流程

```
用户在库存列表找到目标物品
  → 点击 + 或 - 快速调整数量
  → 系统更新数量并记录变更历史
  → 若新数量低于警告线 → 触发提醒逻辑（见 4.3）
  → 若新数量为 0 → 自动加入购物清单（可配置）
```

### 4.3 警告与提醒

#### 功能描述
当物品库存低于用户设定的警告线时，系统通过应用内通知提醒用户及时补充。

#### 数据模型

| 字段 | 类型 | 说明 |
|------|------|------|
| 警告线数量 | 数字 | 低于此值触发提醒，默认为 1 |
| 警告状态 | 枚举 | 正常 / 警告 / 缺货 |
| 提醒方式 | 枚举 | 应用内通知（本期）|
| 是否已读 | 布尔 | 用户是否已查看该提醒 |

#### 功能点

**警告线设置**
- 每个物品可单独设置警告线数量
- 支持批量设置同一分类下所有物品的默认警告线
- 警告线可设为 0（即仅在完全缺货时提醒）

**提醒触发规则**
- 库存数量 ≤ 警告线：触发"库存不足"提醒
- 库存数量 = 0：触发"已缺货"提醒（更高优先级）
- 同一物品同一天内只触发一次提醒，避免骚扰

**应用内通知中心**
- 顶部导航栏显示未读提醒数量角标
- 通知中心列出所有未处理的库存警告
- 每条通知支持"加入购物清单"和"忽略"两个快捷操作
- 忽略后该物品当天不再提醒

#### 业务流程

```
库存数量变更
  → 系统检查是否低于警告线
  → 是 → 生成通知记录 → 显示在通知中心
  → 用户点击通知 → 选择"加入购物清单"或"忽略"
```

### 4.4 购物清单

#### 功能描述
购物清单是库存管理的延伸，记录需要补购的物品，支持自动生成和手动添加，购买完成后可一键更新库存。

#### 数据模型

| 字段 | 类型 | 说明 |
|------|------|------|
| 物品 | 关联 | 关联到物品库中的物品 |
| 需购数量 | 数字 | 计划购买的数量 |
| 来源 | 枚举 | 自动生成（库存不足）/ 手动添加 / 定期重复 |
| 状态 | 枚举 | 待购买 / 已购买（待入库）/ 已完成 |
| 实际购买数量 | 数字 | 实际购买的数量（可与计划不同）|
| 购买价格 | 数字 | 选填，用于预算统计 |
| 添加人 | 用户 | 谁添加了这条清单项 |

#### 功能点

**自动生成**
- 物品库存触达警告线时，可一键将其加入购物清单
- 支持"一键生成购物清单"：将所有警告/缺货物品批量加入

**手动添加**
- 用户可手动添加任意物品到购物清单（不限于库存不足的物品）
- 支持添加系统中没有的临时物品（不关联物品库）

**购物清单管理**
- 支持调整需购数量
- 支持删除清单项
- 支持按分类分组展示，方便在超市按区域采购
- 支持分享清单（生成文本或链接，发给家庭成员）

**购买完成入库**
- 勾选已购买的物品，填写实际购买数量和价格
- 点击"完成入库"，系统自动将数量累加到对应物品的库存
- 入库后该清单项状态变为"已完成"，从待购列表移除

#### 业务流程

```
方式一（自动）：
  库存不足 → 通知中心 → 用户点击"加入购物清单"→ 清单项创建

方式二（手动）：
  用户进入购物清单页 → 点击"添加" → 选择物品 → 填写数量 → 保存

购买完成：
  用户在超市购买后 → 勾选已购物品 → 填写实际数量和价格
  → 点击"入库" → 库存自动更新 → 清单项标记为已完成
```

### 4.5 保质期管理

#### 功能描述
针对食品、药品等有时效性的物品，支持录入保质期并在临期时提醒用户，同时支持同一物品多批次管理。

#### 数据模型（批次记录）

| 字段 | 类型 | 说明 |
|------|------|------|
| 所属物品 | 关联 | 关联到物品库 |
| 批次数量 | 数字 | 本批次的数量 |
| 生产日期 | 日期 | 选填 |
| 保质期至 | 日期 | 必填（启用保质期追踪时）|
| 状态 | 枚举 | 正常 / 临期（≤7天）/ 已过期 |
| 备注 | 文本 | 如"2024年双十一购入" |

#### 功能点

**保质期录入**
- 物品详情页可开启"保质期追踪"开关（默认关闭，食品/药品分类默认开启）
- 开启后，每次入库时需填写保质期日期
- 支持同一物品录入多个批次（不同保质期）

**批次管理**
- 物品详情页展示所有批次列表，按保质期从近到远排序
- 消耗时默认优先消耗最近过期的批次（FEFO 原则）
- 支持手动指定消耗某个批次

**过期提醒**
- 提前天数可配置，默认提前 7 天提醒
- 提醒分级：7 天内（黄色警告）、3 天内（橙色）、已过期（红色）
- 过期物品在库存列表中显示醒目标记
- 已过期物品不计入有效库存数量

**使用寿命（家电类）**
- 家电类物品支持录入"购买日期"和"预计使用年限"
- 到期前 30 天提醒用户关注设备状态

#### 业务流程

```
用户入库时（开启保质期追踪的物品）：
  填写入库数量 → 填写保质期日期 → 系统创建批次记录

系统每日定时检查：
  扫描所有批次 → 计算距过期天数
  → ≤7天 → 生成临期提醒通知
  → 已过期 → 标记为过期，从有效库存中移除
```

### 4.6 位置追踪

#### 功能描述
记录每种物品的存放位置，支持多级位置层级，帮助家庭成员快速找到物品。

#### 数据模型

**位置层级**：房间 → 家具/区域 → 具体位置

| 字段 | 类型 | 示例 |
|------|------|------|
| 一级位置（房间）| 文本 | 厨房、卫生间、客厅、卧室 |
| 二级位置（家具）| 文本 | 冰箱、橱柜、药箱、储物柜 |
| 三级位置（具体）| 文本 | 第一层、左侧、门后 |

#### 功能点

**位置管理**
- 用户可自定义位置体系（房间和家具名称）
- 系统预设常见位置供快速选择
- 支持为物品设置多个存放位置（如"米：厨房橱柜 + 阳台储物箱"）

**位置展示**
- 物品详情页显示完整位置路径，如"厨房 > 橱柜 > 第二层"
- 支持"按位置浏览"视图：以房间为维度查看该区域所有物品

**位置搜索**
- 搜索物品时，结果中显示存放位置
- 支持按位置筛选（如"查看冰箱里的所有物品"）

**物品移动**
- 支持"移动物品"操作，更新存放位置并记录变更历史

#### 业务流程

```
用户添加/编辑物品
  → 点击"设置位置"
  → 选择或新建房间 → 选择或新建家具 → 填写具体位置
  → 保存 → 物品详情页显示位置信息

用户查找物品：
  搜索物品名称 → 搜索结果显示位置 → 用户直接找到
```

### 4.7 家庭成员协作

#### 功能描述
支持多个家庭成员共享同一个物品库，所有成员实时查看相同的库存数据。

#### 数据模型

| 字段 | 类型 | 说明 |
|------|------|------|
| 家庭空间 | 实体 | 一个家庭对应一个独立的数据空间 |
| 成员角色 | 枚举 | 管理员 / 普通成员 |
| 邀请码 | 文本 | 用于邀请新成员加入 |

#### 权限设计

| 操作 | 管理员 | 普通成员 |
|------|--------|----------|
| 查看库存 | ✅ | ✅ |
| 修改库存数量 | ✅ | ✅ |
| 添加/编辑物品 | ✅ | ✅ |
| 删除物品 | ✅ | ❌ |
| 管理分类/分组 | ✅ | ❌ |
| 邀请/移除成员 | ✅ | ❌ |
| 修改家庭设置 | ✅ | ❌ |

#### 功能点

**家庭空间创建**
- 注册后引导用户创建家庭空间或加入已有家庭
- 一个用户只能属于一个家庭空间

**成员邀请**
- 管理员生成邀请链接或邀请码，有效期 24 小时
- 被邀请人通过链接注册/登录后自动加入家庭

**实时同步**
- 任意成员修改库存后，其他成员刷新页面即可看到最新数据
- 本期不要求 WebSocket 实时推送，轮询或手动刷新即可

**修改历史**
- 所有成员的操作均记录在修改历史中
- 历史记录显示操作人昵称

#### 业务流程

```
管理员创建家庭空间
  → 生成邀请链接 → 发送给家庭成员
  → 成员点击链接 → 注册/登录 → 自动加入家庭
  → 所有成员共享同一份库存数据
```

### 4.8 预算统计

#### 功能描述
记录每次购物的花费，提供月度采购支出统计，帮助家庭了解消费结构。

#### 数据模型

| 字段 | 类型 | 说明 |
|------|------|------|
| 关联购物清单项 | 关联 | 来源于购物清单入库操作 |
| 金额 | 数字 | 本次购买花费（元）|
| 购买日期 | 日期 | 自动取入库日期 |
| 分类 | 文本 | 继承自物品分类 |
| 记录人 | 用户 | 执行入库操作的成员 |

#### 功能点

**费用录入**
- 购物清单入库时，可选填每项物品的购买价格
- 支持手动添加未通过购物清单入库的费用记录

**月度统计**
- 统计页展示当月总支出
- 按分类（食品/日用品/药品等）展示支出占比（饼图）
- 支持查看历史月份数据，最多保留 12 个月

**简单分析**
- 展示本月 vs 上月支出对比
- 展示支出最高的 Top 5 物品

#### 业务流程

```
用户完成购物清单入库
  → 填写各物品购买价格（选填）
  → 系统汇总本次采购总金额
  → 统计页自动更新当月数据
```

### 4.9 定期重复购买

#### 功能描述
对于需要定期补充的物品（如每月买一袋米），支持设置重复规则，系统自动在指定时间将其加入购物清单。

#### 数据模型

| 字段 | 类型 | 说明 |
|------|------|------|
| 物品 | 关联 | 关联到物品库 |
| 重复周期 | 枚举 | 每周 / 每两周 / 每月 / 自定义天数 |
| 下次触发日期 | 日期 | 系统计算 |
| 购买数量 | 数字 | 每次自动加入购物清单的数量 |
| 是否启用 | 布尔 | 可暂停不删除 |

#### 功能点

**规则设置**
- 在物品详情页设置"定期购买"规则
- 支持选择重复周期和每次购买数量
- 支持设置开始日期

**自动触发**
- 到达触发日期时，系统自动将物品加入购物清单
- 加入时标注来源为"定期重复"
- 触发后自动计算下次触发日期

**规则管理**
- 统一的"定期购买"管理页，展示所有规则和下次触发时间
- 支持暂停、恢复、删除规则

#### 业务流程

```
用户在物品详情页设置定期购买规则
  → 填写周期和数量 → 保存

系统每日定时任务：
  检查所有启用的规则 → 找到今日应触发的规则
  → 自动创建购物清单项 → 通知用户
```

## 5. 非功能性需求

### 5.1 性能
- 页面首屏加载时间 ≤ 2 秒（正常网络环境）
- 库存列表支持 500+ 物品流畅展示（虚拟滚动）
- 数据修改操作响应时间 ≤ 500ms

### 5.2 可用性
- Web 端支持主流浏览器：Chrome、Safari、Edge（最新两个版本）
- 响应式布局，支持手机浏览器访问（屏幕宽度 ≥ 375px）
- 关键操作（增减库存、查看清单）在手机端单手可操作

### 5.3 数据安全
- 用户数据按家庭空间隔离，不同家庭数据严格隔离
- 支持用户选择数据存储方式：本地存储（IndexedDB）或云端同步
- 云端数据传输使用 HTTPS 加密
- 支持数据导出（JSON/CSV 格式），用户对自己的数据有完整控制权

### 5.4 可靠性
- 云端数据每日自动备份
- 本地存储模式下，支持手动导出备份文件
- 关键操作（删除物品、清空清单）需二次确认

### 5.5 可扩展性
- 数据模型预留扩展字段，便于后续添加条码、图片识别等功能
- 通知系统设计为可插拔，便于后续接入推送通知

## 6. 优先级与分阶段计划

### 第一阶段 P1（MVP，建议 6～8 周）

**目标**：交付可用的核心库存管理闭环

| 功能 | 说明 |
|------|------|
| 用户注册/登录 | 邮箱注册，支持创建/加入家庭空间 |
| 物品管理（4.1）| 增删改查、分类分组标签、搜索 |
| 库存管理（4.2）| 数量记录、快速增减、修改历史 |
| 警告与提醒（4.3）| 警告线设置、应用内通知中心 |
| 购物清单（4.4）| 自动生成、手动添加、入库更新库存 |
| 保质期管理（4.5）| 保质期录入、批次管理、过期提醒 |

**验收标准**：用户能完成"添加物品 → 消耗库存 → 收到警告 → 生成购物清单 → 购买入库"的完整闭环。

---

### 第二阶段 P2（建议 4～6 周）

**目标**：提升协作体验和数据价值

| 功能 | 说明 |
|------|------|

| 家庭成员协作（4.7）| 邀请成员、权限管理、修改历史 |
| 预算统计（4.8）| 月度支出统计、分类占比图表 |

---

### 第三阶段 P3（建议 3～4 周）

**目标**：自动化与智能化

| 功能 | 说明 |
|------|------|
| 定期重复购买（4.9）| 重复规则、自动生成清单项 |
| PWA 支持 | 支持添加到手机桌面、离线访问 |
| 数据导出 | 导出库存报告（CSV/JSON）|

## 7. 可行性分析

### 7.1 技术复杂度评估

| 模块 | 复杂度 | 主要挑战 |
|------|--------|----------|
| 物品管理 | 低 | 标准 CRUD，无特殊挑战 |
| 库存管理 | 低 | 并发写入冲突处理需注意 |
| 警告与提醒 | 低 | 触发逻辑简单，通知中心标准实现 |
| 购物清单 | 低 | 状态流转逻辑需仔细设计 |
| 保质期管理 | 中 | 批次管理和 FEFO 消耗逻辑有一定复杂度 |
| 位置追踪 | 低 | 多级层级数据结构设计 |
| 家庭协作 | 中 | 多租户数据隔离、邀请机制 |
| 预算统计 | 低 | 聚合查询，图表渲染 |
| 定期重复购买 | 低 | 定时任务调度 |

### 7.2 推荐技术栈

| 层次 | 推荐方案 | 理由 |
|------|----------|------|
| 前端 | React + TypeScript | 生态成熟，组件复用性强 |
| 后端 | Node.js (Express) 或 Python (FastAPI) | 开发效率高，适合小团队 |
| 数据库 | PostgreSQL | 关系型数据，支持复杂查询 |
| 本地存储 | IndexedDB (Dexie.js) | 支持离线模式 |
| 部署 | Vercel（前端）+ Railway/Render（后端）| 低成本，快速上线 |

## 8. 风险与对策

| 风险 | 概率 | 影响 | 对策 |

| 功能范围蔓延导致延期 | 中 | 高 | 严格按阶段交付；P1 只做核心闭环，其余功能推后 |
