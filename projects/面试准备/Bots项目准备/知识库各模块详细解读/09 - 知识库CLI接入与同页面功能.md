# 知识库 CLI 接入与同页面功能

> 本篇讲清楚"知识库页面的 CLI 接入是什么"以及"与知识库同页面的其他功能模块各自是什么"。

---

## 一、CLI 接入功能

### 1.1 本质是什么

知识库页面上的"CLI 接入"实际上是平台的通用开放 API 令牌系统，不是专门为知识库设计的功能。

用户在前端填写名称标识、选择要绑定的知识库/智能体/工作流/能力，点击生成后，系统创建一个 32 位随机令牌和一组权限记录。经管理员审批后，外部系统（如 CI/CD 管道、命令行工具）可以在 HTTP 请求头中携带这个令牌来调用平台的智能体 API。

### 1.2 使用场景

比如 CI/CD 管道想自动调用智能体检查代码质量——管道脚本里带上这个令牌发 HTTP 请求，智能体就会对话并自主检索绑定的知识库。不需要人在浏览器里操作。

### 1.3 详细文档

CLI 接入与开放 API 的完整底层原理有单独的文档详细介绍：`09-知识库CLI接入与开放API底层原理.md`。

## 二、与知识库同页面的其他功能

从界面左侧菜单看到的其他功能，它们与知识库的关系如下：

### 2.1 Prompt 模板

这不是知识库的子功能，而是"验证规则"体系下的一个模块。

本质是给自动化质检/校验流程配置用的提示词模板（区分系统提示词和用户提示词），支持分类管理和变量占位符。它和知识库没有直接绑定关系，主要服务于"校验智能体回复质量"这类场景。

比如：你想检查智能体的回复是否包含了知识库中的正确信息，可以配置一个 Prompt 模板让另一个 AI 来校验。

### 2.2 AI 专家 / 专家模板

代码里没有"AI 专家"这个独立概念，它其实是"Bot 模板"功能在前端的叫法。

可以理解为：专家模板是蓝图，AI 专家是运行实例。

- 专家模板：预置了配置文件、技能、规则等一整套东西的"模板"。比如"代码审查专家"模板里预设了代码审查相关的系统提示词、技能包、知识库绑定
- AI 专家：用户拿一个专家模板创建出的真实可用的智能体

模板系统支持完整的商业化功能：

- 发布到市场（让其他用户使用）
- 付费购买
- 创作者分成
- 导出导入
- 分组管理
- 版本管理

### 2.3 Skill 技能

技能的创建和发布在另一个独立服务中，本仓库只负责技能的安装、调用和鉴权。

技能和知识库的关系：知识库可以被"技能化"——把知识库包装成一种特殊技能安装到智能体容器里（详见第 04 篇）。但技能的概念比知识库更广——技能还包括协作技能、定时任务技能、代码操作技能等。

### 2.4 API 工具

API 工具可能是前端对某类工作流节点的包装。在工作流中可以配置"调用外部 API"节点，前端把这些可调用的 API 集中管理展示，就叫"API 工具"。

它和知识库没有直接关系，只是恰好在同一个左侧菜单下。

### 2.5 MCP 服务

MCP（Model Context Protocol）不是独立管理页面，而是嵌在智能体配置中的一个字段。

用户编辑智能体时配置 MCP 服务器信息（服务器地址、连接方式、鉴权信息等），随智能体配置一起保存。系统支持三种 MCP 连接方式：stdio（本地命令行）、sse（服务器推送）、http（HTTP 请求）。

MCP 和知识库的关系：两者都是给智能体"扩展能力"的方式——知识库扩展了"查资料"能力，MCP 扩展了"调用外部工具"能力。但实现机制完全不同：知识库走的是"技能说明书 + AI 自主检索"路径，MCP 走的是"标准协议 + 工具注册"路径。

## 四、面试怎么说

问：知识库页面上的 CLI 接入是什么？

答：CLI 接入是平台的通用开放 API 令牌系统，不是专门为知识库设计的。用户选择要绑定的知识库/智能体/工作流，生成一个 32 位随机令牌，经管理员审批后，外部系统可以在 HTTP 请求头中携带这个令牌来调用智能体 API。比如 CI/CD 管道可以带令牌自动调用智能体检查代码质量，智能体在对话中自主检索绑定的知识库。

问：知识库页面上还有哪些功能？它们和知识库什么关系？

答：还有 Prompt 模板（服务于验证规则，和知识库无直接关系）、AI 专家（本质是 Bot 模板，可以预置知识库绑定）、Skill 技能（技能安装管理，知识库可以被"技能化"）、API 工具（工作流节点的包装）、MCP 服务（嵌入智能体配置中的外部工具协议）。它们只是恰好在同一个左侧菜单下，功能上各自独立，只有"AI 专家"和知识库有直接关系——模板可以预设知识库绑定。
