### [Current Focus]
`PLANT-002` 已完成：植物 editor contract 现在已经独立成共享表单层。[`plantSchema`](../app/src/features/plants/plantSchema.ts) 统一处理 validation 和 DTO mapping，[`usePlantForm`](../app/src/features/plants/usePlantForm.ts) 维护可复用 draft state，[`PlantForm`](../app/src/features/plants/PlantForm.tsx) 负责字段布局和图片字段集成。下一线任务切换为 `PLANT-003`。

### [Key Decisions]
- `PLANT-002` 没有新增后端接口，只产出了前端共享契约：表单 draft、校验结果和提交 payload mapping。
- 植物表单规则按产品规格落地：`name` 必填，`description`、`note`、`location`、`imageStorageId` 保持可选；空白字符串在 DTO 层统一折叠成 `null`。
- 当前 domain/schema 侧历史上仍是 `notes` 复数名，这轮 editor contract 对外统一用 `note`，但 edit hydration 会兼容从现有 `Plant.notes` 载入，避免后续 create/edit 再做 shape conversion。

### [Blockers & Solutions]
- 当前共享 UI 里只有单行 `InputField`，没有 textarea primitive；这轮把多行字段局部收在 `PlantForm` 内，没有越界扩展新的全局组件任务。
- `PLANT-002` metadata 没列测试文件，但为了证明 create/edit 共用 contract 不跑偏，补了 `PlantForm.test.tsx`；这是本轮唯一的最小超范围改动。
- 浏览器级移动端验证依旧受宿主 Playwright 限制影响，所以这轮以前端组件测试覆盖字段层级、错误提示和 edit 预填充为主，没有伪造浏览器截图结果。

### [Verification]

  - edit 预填充可以从现有 `Plant.notes` 和 `imageStorageId` 正确映射到共享 editor state

### [Dead Ends]
- 不要在 `PLANT-002` 里顺手接 create/edit mutation；这会越过 `PLANT-003` 和 `PLANT-004`。
- 不要把表单 draft shape 设计成 create 和 edit 两套不同结构；这正是本任务要避免的 shape conversion 问题。
