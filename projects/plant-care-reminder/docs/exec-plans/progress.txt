### [Current Focus]
`PLANT-003` 已完成：植物创建流已经接通。后端 [plants.ts](../app/convex/plants.ts) 新增 `createPlant` mutation，前端 [CreatePlantPage.tsx](../app/src/features/plants/CreatePlantPage.tsx) 把共享 `PlantForm` 接到了 `/plants/new`，成功后会回到 `/plants`，并保留轻量 success flag 作为列表占位页反馈。下一线任务切换为 `PLANT-004`。

### [Key Decisions]
- `createPlant` 的 API 契约沿用任务定义里的 `note` 单数名，但写入数据库时映射到现有 schema 字段 `notes`，避免为了本轮创建流去改已有数据字段命名。
- `/plants/new` 被纳入受保护路由集合，`BottomNav` 的 Plants tab 也改成对整个 `/plants*` 路径族高亮，避免进入新建页后导航状态错位。
- 当前 `/plants` 还不是正式列表页，所以这轮只把它升级成“列表占位 + 新建入口 + 成功反馈”，不提前实现真实 plant cards，保持 `PLANT-005` 的范围干净。

### [Blockers & Solutions]
- Convex 类型检查一开始卡在 `requireCurrentFamilyMember` 的返回类型仍带 `null`，即使运行时 guard 已保证有值；这轮通过显式收窄 helper 返回类型解决，避免 create mutation 在 `familyId` / `createdBy` 上继续报错。
- 创建页最初只有成功路径，没有 mutation 失败提示；这轮已在 `CreatePlantPage` 内补上页内错误文案，保证失败路径可见。
- 浏览器级移动端验证依旧受宿主 Playwright 限制影响，所以这轮以 `npm run test` 和 `npx convex dev --once --typecheck enable` 为主，没有伪造浏览器截图结果。
