### [Current Focus]
`CARE-001` 已完成：reminders 模块现在已经有一套可复用的共享 task contract。新增 [taskTypes.ts](../app/src/features/tasks/taskTypes.ts) 统一维护 task type 值、展示文案、custom task 校验和 UI options；新增 [scheduling.ts](../app/src/features/tasks/scheduling.ts) 统一维护 interval 校验与 `computeNextDueAt`。我还把 [formatters.ts](../app/src/lib/formatters.ts)、[domain.ts](../app/src/types/domain.ts) 和 [validators.ts](../app/convex/lib/validators.ts) 接到这套共享来源，避免后续 create/edit/complete 再各自维护一份 task type 列表。下一线任务切换为 `CARE-002`。

### [Key Decisions]
- task type 值现在只有一份共享来源，`src` 侧 UI 和 `convex` 侧 validators 都消费同一份 `careTaskTypeValues`。
- custom task 的“仅 custom 类型必填名称”规则已经收口到 `validateCustomTaskName`，后续表单不需要各自重写。
- next-due 计算统一走 `computeNextDueAt`，并在 helper 层直接拒绝非法 `intervalDays`，避免后续 create/edit/complete 流程各写一版时间运算。

### [Blockers & Solutions]
- 现有代码里 task label helper 原本散在 `lib/formatters.ts`，而 task type 值又分别存在 `domain.ts` 和 `validators.ts`；这轮通过共享 helper 源头收束，避免后续 reminders 流程一开始就带着重复定义。
- `plantTasks` schema 当前字段名还是 `customLabel`，而执行清单文案写的是 `customTaskName`；这轮先在共享 helper 层统一业务语义，后续 create/edit 表单可以只做 DTO 映射，不再重复业务规则。
- 浏览器级验证对这轮没有增量价值，因为 `CARE-001` 是纯共享 contract；优先用单测和 typecheck 钉住 helper 行为。
