### [Current Focus]
`CARE-002` 已完成：`/plants/:plantId/tasks/new` 现在已经是可用的新建 care task 流。后端新增 [tasks.ts](../app/convex/tasks.ts)，提供 `getTaskCreationPlant` 和 `createPlantTask`，会校验 plant/family ownership、拒绝 archived plant、复用共享 helper 计算 `nextDueAt`，并把新任务写进 `plantTasks`；前端新增 [CreateTaskPage.tsx](../app/src/features/tasks/CreateTaskPage.tsx) 与 [TaskForm.tsx](../app/src/features/tasks/TaskForm.tsx)，同时把 [router.tsx](../app/src/app/router.tsx)、[AppShell.tsx](../app/src/app/AppShell.tsx) 和 [PlantDetailPage.tsx](../app/src/features/plants/PlantDetailPage.tsx) 接上了 `/plants/:plantId/tasks/new` 路由和 `Add routine` 入口。下一线任务切换为 `CARE-003`。

### [Key Decisions]
- create-task 后端写路径独立放在 `convex/tasks.ts`，不继续往 `plants.ts` 里堆 reminders 逻辑。
- create route 直接消费 `CARE-001` 的 task type / custom validation / scheduling helper，不复制任何规则。
- archived plants 在 create-task query 和 mutation 两侧都被拦掉，避免前端只靠 UI 入口做保护。

### [Blockers & Solutions]
- 当前测试 harness 只有单 queryResult / 单 mutation handler，所以 create route 查询被刻意压成一个 `getTaskCreationPlant`，避免为了 `CARE-002` 提前扩展复杂 mock 多路由。
- `customTaskName` 的产品语义需要映射到 schema 字段 `customLabel`；这轮在 mutation 层做了 DTO translation，没有把这个差异泄漏到前端 form。
- 浏览器级验证依旧受宿主 Playwright 限制影响，所以这轮优先用 smoke tests 覆盖 route、validation、mutation payload 和跳转结果。
