### [Current Focus]
`PLANT-007` 已完成：植物详情页现在已经支持软归档和恢复。后端 [plants.ts](../app/convex/plants.ts) 新增了 `setPlantArchivedState`，只会 patch `plants.isArchived`、`archivedAt` 和 `updatedAt`，不会触碰任何 `plantTasks` 或 `taskCompletionLogs`；前端新增 [ArchivePlantAction.tsx](../app/src/features/plants/ArchivePlantAction.tsx)，并接到 [PlantDetailPage.tsx](../app/src/features/plants/PlantDetailPage.tsx) 与 [PlantHeroCard.tsx](../app/src/features/plants/PlantHeroCard.tsx)。现在家庭成员必须先确认，才能 archive 或 restore；archive 后植物会继续从 active plant views 中消失，而详情页会保留 restore 落点。下一线任务切换为 `CARE-001`。

### [Key Decisions]
- “active views 隐藏 archived plants” 继续放在后端 query contract 层处理，而不是前端拉全量后筛；现有 `/plants` 列表仍只吃 `isArchived === false` 的记录。
- archive / restore 复用同一个 mutation，避免把“恢复”做成一套独立的写路径，减少未来 reminders 模块接入后的分叉状态。
- 已归档植物的 restore 落点保留在 `/plants/:plantId` 详情页，而不是强制依赖未来的 archived list，这样当前 MVP 就能闭合 restore 行为。

### [Blockers & Solutions]
- 当前仓库里还没有 reminders 模块，所以 archive 后“从 due views 消失”的完整运行态证据还要等 `CARE-005` 等任务落地；这轮先把软归档数据面和 detail action 闭合。
- 由于当前没有 archived list，restore 如果依赖列表入口会变成死路；本轮通过 detail 页本地状态覆盖解决了这个闭环。
- 浏览器级移动端验证依旧受宿主 Playwright 限制影响，所以这轮优先用 smoke tests 覆盖确认弹层、mutation 参数和归档后 UI 状态切换。
