### [Current Focus]
`CARE-003` 已完成：现有 care task 的 edit、enable-disable 和 delete 流已经闭合。后端 [tasks.ts](../app/convex/tasks.ts) 新增了 `getTaskForEdit`、`updatePlantTask` 和 `deletePlantTask`，会按当前家庭校验 task/plant ownership、复用共享 helper 重新计算 `nextDueAt`，并支持显式删除；前端新增 [EditTaskPage.tsx](../app/src/features/tasks/EditTaskPage.tsx) 与 [DeleteTaskAction.tsx](../app/src/features/tasks/DeleteTaskAction.tsx)，同时扩展了 [TaskForm.tsx](../app/src/features/tasks/TaskForm.tsx)、[router.tsx](../app/src/app/router.tsx) 和 [AppShell.tsx](../app/src/app/AppShell.tsx)，把 `/plants/:plantId/tasks/:taskId/edit` 真正接起来。下一线任务切换为 `CARE-004`。

### [Key Decisions]
- task 的 create / edit / delete 都收口在同一个 `convex/tasks.ts` 边界里，避免 reminders 写路径继续分散。
- edit page 继续复用 `TaskForm`，通过 `title` / `description` / `actionsSlot` 扩展状态和危险操作，而不是起第二套 editor contract。
- disabled task 不删除记录，只 patch `enabled: false` 并重算 `nextDueAt`，保持后续 completion/history 扩展的连续性。

### [Blockers & Solutions]
- 当前测试 harness 的所有 mutation 仍共享一个 mock handler，所以 edit / delete 覆盖是按单页面单动作分开的，避免多 mutation 混用时断言互相污染。
- `updatePlantTask` 需要基于历史 completion baseline 重算 `nextDueAt`，这轮把这条规则放在 mutation 层，前端不自行推导。
- 浏览器级验证依旧受宿主 Playwright 限制影响，所以这轮优先用 smoke tests 覆盖预填充、disable payload 和 delete confirmation。
