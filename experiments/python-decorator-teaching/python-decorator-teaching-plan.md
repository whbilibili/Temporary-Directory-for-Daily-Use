## 第一期：装饰器的本质与核心用法

### 教学目标

让学员理解装饰器不是"魔法语法"，而是 Python 函数式编程能力的自然延伸。掌握装饰器的心智模型后，能独立编写和调试常见装饰器。

---

### 本期知识点（按讲解顺序）

#### 1. 前置知识回顾（铺垫，快速过）

- 函数是一等公民：函数可以赋值给变量、作为参数传递、作为返回值
- 闭包（Closure）：内层函数捕获外层函数的变量

> 这两点不展开讲，只用简短代码示例唤醒记忆，确保后续理解无障碍。

#### 2. 装饰器的本质（核心概念）

- 装饰器 = 接收函数作为参数，返回新函数的高阶函数
- `@decorator` 语法糖等价于 `func = decorator(func)`
- 用"包装礼物"的比喻：原函数是礼物，装饰器是包装纸，包装后礼物还在，但外观和附加功能变了

#### 3. 第一个装饰器：无参装饰器

- 经典三层结构：外层函数（装饰器本体）→ 内层函数（wrapper）→ 调用原函数
- 完整示例：计时装饰器（`@timer`）
- 逐行拆解执行流程
- 强调 `*args, **kwargs` 的作用：让装饰器适配任意签名的函数

#### 4. `functools.wraps` 的必要性

- 问题演示：不加 wraps 时，`__name__`、`__doc__` 丢失
- 解决方案：`@functools.wraps(func)` 保留原函数元信息
- 规范：写装饰器时必须加，这是工程习惯

#### 5. 带参数的装饰器

- 为什么需要：想让装饰器行为可配置（如重试次数、日志级别）
- 结构：三层嵌套 → 最外层接收装饰器参数，中间层接收被装饰函数，最内层是 wrapper
- 示例：`@retry(max_attempts=3)` 重试装饰器
- 心智模型：`@retry(3)` 等价于 `func = retry(3)(func)`

#### 6. 多个装饰器叠加

- 执行顺序：从下往上装饰（靠近函数的先执行），从上往下调用
- 示例演示叠加顺序
- 类比：穿衣服（先穿内衣再穿外套）vs 脱衣服（先脱外套再脱内衣）

#### 7. 实战案例（串联前面所有知识）

- 案例 1：权限校验装饰器 `@require_login`
- 案例 2：缓存装饰器 `@cache_result`（简化版 lru_cache）
- 案例 3：日志装饰器 `@log_calls`

#### 8. 常见陷阱与调试技巧

- 忘记调用：`@decorator` vs `@decorator()`（带参装饰器忘加括号）
- 装饰器吞异常：wrapper 中 try/except 不当导致错误被静默
- 返回值丢失：wrapper 中忘记 `return func(*args, **kwargs)`

### 本期不涉及，后续再讲的内容

| 知识点 | 计划期数 | 原因 |
|--------|----------|------|
| 类装饰器（用类实现装饰器） | 第二期 | 需要先理解 `__call__` 魔术方法 |
| 装饰类的装饰器（装饰器作用于类而非函数） | 第二期 | 需要理解类的创建过程 |
| `@property`、`@staticmethod`、`@classmethod` 源码解析 | 第二期 | 属于描述符协议，概念跨度大 |
| 装饰器与元类的关系 | 第三期 | 需要元类基础 |
| 装饰器在异步编程中的应用（`async` 装饰器） | 第三期 | 需要 asyncio 基础 |
| 装饰器的性能影响与优化 | 第三期 | 需要 profiling 知识 |
| 标准库中的装饰器全景（`dataclass`、`contextmanager` 等） | 第二/三期 | 各自有独立知识背景 |
| 装饰器模式 vs 装饰器语法（设计模式视角） | 第三期 | 偏设计思想，适合进阶 |

### 教学节奏建议

1. 前置回顾（2 分钟）→ 快速唤醒
2. 本质讲解 + 第一个装饰器（重点，10 分钟）→ 建立心智模型
3. wraps + 带参装饰器（8 分钟）→ 工程规范
4. 叠加顺序（3 分钟）→ 理解组合
5. 实战案例（7 分钟）→ 巩固应用
6. 陷阱总结（3 分钟）→ 避坑指南
