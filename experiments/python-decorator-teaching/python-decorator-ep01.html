1. 前置知识回顾

在理解装饰器之前，需要确认两个前置概念已经就位。这里不展开讲，只用简短代码唤醒记忆。

函数是一等公民

函数可以赋值给变量、作为参数传递、作为返回值返回——和普通数据没有区别。

Python 
def greet(name):
    return f"Hello, {name}!"

# 函数赋值给变量
say_hi = greet
print(say_hi("World"))  # Hello, World!

# 函数作为参数传递
def call_twice(func, arg):
    func(arg)
    func(arg)

闭包（Closure）

内层函数可以"记住"外层函数的变量，即使外层函数已经执行完毕。

Python 
def make_multiplier(factor):
    def multiply(x):
        return x * factor  # factor 被"记住"了
    return multiply

double = make_multiplier(2)
print(double(5))  # 10
💡

闭包就像一个背包：内层函数离开外层函数时，把需要的变量装进背包带走了。无论它走到哪里，都能从背包里取出这些变量来用。

2. 装饰器的本质

一句话定义：装饰器 = 接收函数作为参数，返回新函数的高阶函数。

@decorator 只是一个语法糖，它等价于：

语法糖写法 
@decorator
def func():
    ...
≡
等价展开 
def func():
    ...
func = decorator(func)
💡

包装礼物的比喻：原函数是礼物，装饰器是包装纸。包装后礼物还在里面，但外观变了，还可能附加了蝴蝶结（额外功能）。拆开包装（调用函数），礼物本身的功能不变。

装饰器执行流程

定义原函数
→
传入装饰器
→
返回新函数
→
替换原函数名

3. 第一个装饰器：无参装饰器

经典三层结构

外层函数
装饰器本体
→
内层函数
wrapper
→
调用原函数
func(*args, **kwargs)

完整示例：计时装饰器

Python 
import time

def timer(func):
    """计算函数执行时间的装饰器"""
    def wrapper(*args, **kwargs):
        start = time.time()
        result = func(*args, **kwargs)  # 调用原函数
        end = time.time()
        print(f"{func.__name__} 耗时: {end - start:.4f}s")
        return result  # 别忘了返回！
    return wrapper

@timer
def slow_add(a, b):
    time.sleep(1)
    return a + b

slow_add(1, 2)  # 输出: slow_add 耗时: 1.00xxs
逐行执行流程拆解
Step 1

Python 解释器看到 @timer，执行 slow_add = timer(slow_add)

Step 2

timer(func) 被调用，func 指向原始的 slow_add

Step 3

timer 返回 wrapper 函数，此时 slow_add 这个名字指向了 wrapper

Step 4

调用 slow_add(1, 2) 实际执行的是 wrapper(1, 2)

Step 5

wrapper 内部记录开始时间，调用 func(1, 2)（原始 slow_add），记录结束时间，打印耗时，返回结果

为什么需要 *args, **kwargs？

因为装饰器要能适配任意签名的函数。如果 wrapper 写死了参数，那这个装饰器就只能装饰特定参数的函数，复用性大打折扣。

Python 
# ❌ 只能装饰两个参数的函数
def wrapper(a, b):
    ...

# ✅ 能装饰任意函数
def wrapper(*args, **kwargs):
    ...

4. functools.wraps 的必要性

问题演示

Python 
@timer
def slow_add(a, b):
    """两数相加（慢速版）"""
    ...

print(slow_add.__name__)  # "wrapper" 😱 不是 "slow_add"！
print(slow_add.__doc__)   # None 😱 文档字符串丢了！
⚠️

元信息丢失会导致调试困难、文档生成失败、序列化框架出错。这在生产环境中是真实的坑。

解决方案

Python 
import functools

def timer(func):
    @functools.wraps(func)  # ← 加上这一行！
    def wrapper(*args, **kwargs):
        start = time.time()
        result = func(*args, **kwargs)
        print(f"{func.__name__} 耗时: {time.time()-start:.4f}s")
        return result
    return wrapper

print(slow_add.__name__)  # "slow_add" ✅
print(slow_add.__doc__)   # "两数相加（慢速版）" ✅

工程规范：写装饰器时必须加 @functools.wraps(func)，这是 Python 社区的共识，没有例外。

5. 带参数的装饰器

为什么需要？

有时候我们希望装饰器的行为是可配置的，比如重试次数、日志级别、缓存过期时间等。

结构：三层嵌套

最外层：接收装饰器参数
→
中间层：接收被装饰函数
→
最内层：wrapper（实际执行逻辑）

示例：重试装饰器

Python 
import functools

def retry(max_attempts=3):          # ← 第一层：接收装饰器参数
    def decorator(func):            # ← 第二层：接收被装饰函数
        @functools.wraps(func)
        def wrapper(*args, **kwargs):  # ← 第三层：wrapper
            for attempt in range(1, max_attempts + 1):
                try:
                    return func(*args, **kwargs)
                except Exception as e:
                    print(f"第 {attempt} 次失败: {e}")
                    if attempt == max_attempts:
                        raise
        return wrapper
    return decorator

@retry(max_attempts=5)
def fetch_data(url):
    ...
心智模型：展开语法糖
语法糖 
@retry(max_attempts=5)
def fetch_data(url):
    ...
≡
展开 
def fetch_data(url):
    ...

# 分两步理解：
decorator = retry(max_attempts=5)
fetch_data = decorator(fetch_data)

retry(max_attempts=5) 先执行，返回一个"真正的装饰器"（decorator），然后这个装饰器再去装饰 fetch_data。

6. 多个装饰器叠加

Python 
@decorator_A
@decorator_B
@decorator_C
def func():
    ...

# 等价于：
func = decorator_A(decorator_B(decorator_C(func)))

执行顺序规则：

装饰时（定义阶段）：从下往上（C → B → A）

调用时（运行阶段）：从上往下（A → B → C → func → C → B → A）

💡

穿衣服的比喻：装饰就像穿衣服——先穿内衣（C），再穿衬衫（B），最后穿外套（A）。调用就像脱衣服——先脱外套（A 的前置逻辑），再脱衬衫（B 的前置逻辑），最后到皮肤（原函数）。

完整示例：观察叠加顺序
Python 
def bold(func):
    def wrapper():
        return f"<b>{func()}</b>"
    return wrapper

def italic(func):
    def wrapper():
        return f"<i>{func()}</i>"
    return wrapper

@bold
@italic
def greet():
    return "Hello"

print(greet())
# 输出: <b><i>Hello</i></b>
# italic 先包装，bold 再包装在外面

7. 实战案例

案例 1：权限校验装饰器 @require_login
Python 
import functools

def require_login(func):
    """检查用户是否已登录"""
    @functools.wraps(func)
    def wrapper(*args, **kwargs):
        user = kwargs.get('user') or (args[0] if args else None)
        if not user or not user.is_authenticated:
            raise PermissionError("请先登录！")
        return func(*args, **kwargs)
    return wrapper

@require_login
def view_profile(user):
    return f"欢迎回来，{user.name}！"

这个模式在 Web 框架中非常常见（Django 的 @login_required、Flask 的 @auth.login_required）。

案例 2：缓存装饰器 @cache_result
Python 
import functools

def cache_result(func):
    """简化版 lru_cache：缓存函数结果"""
    cache = {}
    @functools.wraps(func)
    def wrapper(*args):
        if args not in cache:
            cache[args] = func(*args)
            print(f"计算并缓存: {args}")
        else:
            print(f"命中缓存: {args}")
        return cache[args]
    return wrapper

@cache_result
def fibonacci(n):
    if n < 2:
        return n
    return fibonacci(n - 1) + fibonacci(n - 2)

fibonacci(10)  # 只计算 11 次，而非 177 次

标准库提供了更强大的 @functools.lru_cache，但理解原理后你就知道它内部在做什么了。

案例 3：日志装饰器 @log_calls
Python 
import functools
import logging

logging.basicConfig(level=logging.INFO)

def log_calls(func):
    """记录函数调用的参数和返回值"""
    @functools.wraps(func)
    def wrapper(*args, **kwargs):
        args_repr = [repr(a) for a in args]
        kwargs_repr = [f"{k}={v!r}" for k, v in kwargs.items()]
        signature = ", ".join(args_repr + kwargs_repr)
        logging.info(f"调用 {func.__name__}({signature})")
        result = func(*args, **kwargs)
        logging.info(f"{func.__name__} 返回 {result!r}")
        return result
    return wrapper

@log_calls
def add(a, b):
    return a + b

add(3, 4)
# INFO: 调用 add(3, 4)
# INFO: add 返回 7

8. 常见陷阱与调试技巧

⚠️

陷阱 1：带参装饰器忘加括号

Python 
# ❌ 错误：忘记加括号
@retry          # retry 接收的是 func，不是 max_attempts！
def fetch(): ...

# ✅ 正确：即使用默认参数也要加括号
@retry()        # retry() 返回 decorator，decorator 接收 func
def fetch(): ...
⚠️

陷阱 2：装饰器吞异常

Python 
# ❌ 危险：异常被静默吞掉
def safe(func):
    def wrapper(*args, **kwargs):
        try:
            return func(*args, **kwargs)
        except:
            pass  # 😱 所有错误都消失了！
    return wrapper

# ✅ 至少要记录日志
def safe(func):
    def wrapper(*args, **kwargs):
        try:
            return func(*args, **kwargs)
        except Exception as e:
            logging.error(f"{func.__name__} 出错: {e}")
            raise  # 或者根据业务决定是否重新抛出
    return wrapper
⚠️

陷阱 3：返回值丢失

Python 
# ❌ 忘记 return
def my_decorator(func):
    def wrapper(*args, **kwargs):
        print("before")
        func(*args, **kwargs)  # 😱 没有 return！
        print("after")
    return wrapper

# ✅ 正确
def my_decorator(func):
    def wrapper(*args, **kwargs):
        print("before")
        result = func(*args, **kwargs)  # ✅ 保存结果
        print("after")
        return result                    # ✅ 返回结果
    return wrapper
