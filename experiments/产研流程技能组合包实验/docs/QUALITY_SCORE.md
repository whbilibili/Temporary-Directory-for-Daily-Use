# 产研流程技能组合包实验 — 质量标准

## 实验质量目标

| 指标 | 目标 | 当前 | 说明 |
|------|------|------|------|
| 技能覆盖率 | 100% | — | 产研全链路每个阶段至少有一个技能覆盖 |
| 状态传递成功率 | ≥90% | — | 技能间通过 harness 文件传递状态的成功比例 |
| 实验可重现性 | 100% | — | 每个实验结论有可重现的步骤文档 |
| 文档完整性 | 100% | — | `docs/` 下每个文件非空，无未填充的 placeholder |

## 实验记录检查清单

### 通用

- [ ] 实验目标明确：有可验证的成功标准
- [ ] 步骤可重现：他人按文档可独立复现
- [ ] 结论有依据：结论来自观察，不是猜测
- [ ] 失败也记录：失败的实验同样有价值
- [ ] 技能版本标注：记录使用的技能版本或日期

### 技能调用

- [ ] 触发词准确：使用技能描述中的标准触发词
- [ ] 输入完整：技能所需的上下文已准备好
- [ ] 输出验证：技能产物符合预期格式
- [ ] 边界清晰：技能只修改自己负责的文件

### Harness 文件

- [ ] feature-list.json 格式合法（可用 JSON 解析器验证）
- [ ] 每次只有一个任务处于 in_progress 状态
- [ ] progress.txt 行数合理（建议 ≤200 行，超出需裁剪）
- [ ] issues.json 无孤儿工单（状态不是 analyzed_and_ready 的超期条目）

## 反模式清单

| 反模式 | 说明 | 修复方式 |
|--------|------|---------|
| 上下文依赖 | 技能间通过 prompt 传递状态 | 改用 harness 文件 |
| 越界修改 | 技能修改了不属于自己阶段的文件 | 明确技能边界，添加约束 |
| 结论先行 | 先有结论再找证据 | 先观察，再归纳结论 |
| 孤儿实验 | 实验开始后没有 session-handoff | 每次实验结束必须归档 |
| 过度设计 | 实验阶段就引入生产级复杂度 | 最小可验证实验优先 |
