# 产研流程技能组合包实验 — 可靠性

## SLO（实验可靠性目标）

| 指标 | 目标 | 测量方式 | 说明 |
|------|------|---------|------|
| 技能触发成功率 | ≥85% | 人工观察 | 使用标准触发词后技能正确加载 |
| 状态文件一致性 | 100% | JSON 解析验证 | harness 文件格式合法，无损坏 |
| 实验可重现率 | ≥90% | 他人复现测试 | 按文档步骤可独立复现结论 |

## 错误处理模式

### 原则

1. **技能失败不中断实验** — 记录失败原因，尝试降级方案，继续推进
2. **状态文件是真相来源** — 上下文丢失时，从 harness 文件恢复状态
3. **失败也是数据** — 技能调用失败的记录与成功同等重要
4. **幂等操作** — 重复触发同一技能不应产生副作用

### 错误分类

| 类型 | 处理策略 | 示例 |
|------|---------|------|
| 技能未触发 | 检查触发词，尝试同义词 | 技能描述关键词不匹配 |
| 技能输出格式错误 | 人工修正，记录到 issues.json | feature-list.json 格式不合法 |
| 上下文丢失 | 从 harness 文件重建上下文 | 会话中断后重新开始 |
| 技能越界 | 回滚文件，明确边界约束 | 技能修改了不属于自己的文件 |
| 状态文件损坏 | 从 git 历史恢复，记录根因 | JSON 解析失败 |

### 关键 ID 日志规范

每条实验日志必须包含以下字段：

```
时间: YYYY-MM-DD HH:MM
技能: skill-name
阶段: 需求/设计/开发/测试/交付
操作: 触发/输出/验证
结果: 成功/失败/降级
备注: 关键观察或异常说明
```

## 可观测性

### 日志

| 类型 | 路径 | 说明 |
|------|------|------|
| 实验日志 | `docs/design-docs/YYYY-MM-DD-*.md` | 每次实验的详细记录 |
| 执行计划 | `docs/exec-plans/active/` | 当前进行中的计划 |
| 归档计划 | `docs/exec-plans/completed/` | 已完成的计划 |

### 监控

| 指标 | 工具 | 告警阈值 |
|------|------|---------|
| progress.txt 行数 | `wc -l progress.txt` | >200 行需裁剪 |
| in_progress 任务数 | `grep in_progress feature-list.json` | >1 需检查 |
| issues.json 孤儿数 | 人工检查 | >3 个超期未处理 |

### 链路追踪

- 追踪方式: 实验日志（人工记录）
- 关键节点: 每个技能的触发、输出、验证
- 异常标记: 在日志中用 `[WARN]` / `[ERROR]` 前缀标注

## 韧性模式

### 已采用

| 模式 | 应用场景 | 配置 |
|------|---------|------|
| 状态外化 | 会话中断恢复 | harness 文件作为持久化状态 |
| 降级处理 | 技能触发失败 | 人工执行对应阶段任务 |

### 待引入

## 故障恢复

### 恢复手册

| 故障场景 | 影响 | 恢复步骤 |
|---------|------|---------|
| 会话中断 | 上下文丢失 | 读取 CLAUDE.md + progress.txt 重建上下文 |
| harness 文件损坏 | 状态丢失 | 从 git 历史恢复，或从 progress.txt 重建 |
| 技能持续失败 | 阶段阻塞 | 人工执行，记录到 issues.json，继续推进 |

### 回滚策略

- 文件回滚: `git checkout -- <file>` 恢复到上一个已知好状态
- 实验回滚: 将 exec-plans/active/ 中的计划移回 pending 状态
- 配置回滚: 无配置中心，直接编辑文件
