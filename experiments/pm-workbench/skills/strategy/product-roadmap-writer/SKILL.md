# product-roadmap-writer

**产品 Roadmap 制作工具** — 制作清晰、可执行、能对齐团队的产品路线图。

## 触发条件

用户提到：产品路线图、roadmap、产品规划、季度/年度规划、产品计划。

## Roadmap 的本质

好的 Roadmap 是**战略沟通工具**，不是需求清单：
- ❌ 错误认知：Roadmap = 功能列表 + 时间
- ✅ 正确认知：Roadmap = 我们为什么做这些 + 先做什么 + 期望什么结果

## 三种 Roadmap 格式

### 格式一：Now / Next / Later（推荐）
最灵活，适合不确定性高的产品：

```
Now（当前季度）：正在做/确认要做
  - [功能/项目] → 目标：[量化结果]

Next（下个季度）：基本确定，可能小调整
  - [功能/项目] → 目标：[量化结果]

Later（未来）：方向性，不承诺时间
  - [功能/项目] → 为什么在这里：[战略原因]
```

### 格式二：主题型 Roadmap（高层汇报）
按战略主题而非功能列举：

```
2026年产品战略主题：

主题1：提升搜索体验（Q1-Q2）
  Why：搜索是用户发现的核心路径，当前找单率仅43%
  What：智能排序 + 个性化推荐 + 零结果优化
  OKR：搜索找单率→70%，QV YoY +50%

主题2：降低管理成本（Q2-Q3）
  Why：批量管理诉求占订单类客诉21%
  What：批量删除 + 快捷筛选 + 收藏夹
  OKR：订单管理类客诉率下降50%
```

### 格式三：时间线型（团队执行）
精确到月/周，适合内部研发对齐：

```
Q1 2026
  1月：[功能A] - 研发中  [功能B] - 设计中
  2月：[功能A] 上线  [功能C] 启动
  3月：[功能C] 上线  [功能D] 评审

Q2 2026
  4月：[...]
  ...
```

## 执行步骤

### Step 1：收集输入信息
询问用户：
1. 这份 Roadmap 给谁看的？（老板/研发/用户/投资人）
2. 覆盖的时间范围？（季度/半年/年）
3. 当前有哪些已确定的需求/项目？
4. 有哪些战略目标或 OKR？
5. 有哪些资源约束？

### Step 2：生成 Roadmap

**完整输出格式：**

```
【产品 Roadmap】产品：[名称] | 周期：[时间] | 版本：V1.0

战略方向（Why）：
[2-3句话说明这个阶段的核心产品战略]

关键目标（What we're trying to achieve）：
- [目标1]：[指标]
- [目标2]：[指标]

─────────────────────────────────────
NOW（[时间范围]）确定执行
─────────────────────────────────────
主题：[战略主题]
  □ [项目/功能] → 预期：[量化结果]
  □ [项目/功能] → 预期：[量化结果]

─────────────────────────────────────
NEXT（[时间范围]）计划中
─────────────────────────────────────
主题：[战略主题]
  ○ [项目/功能] → Why：[原因]
  ○ [项目/功能] → Why：[原因]

─────────────────────────────────────
LATER（[时间范围]）方向性
─────────────────────────────────────
  ◇ [大方向/探索项]
  ◇ [大方向/探索项]

不做的事（刻意排除）：
  × [明确不做的] → 原因：[为什么]

风险与依赖：
  ⚠ [关键风险1]
  ⚠ [关键依赖1]（依赖谁/什么）
```

### Step 3：Roadmap 健康度检查

- ✅ 每项都有"为什么做"（不只是功能描述）
- ✅ 有量化目标（不是"提升体验"）
- ✅ LATER 里的东西真的不急（不是延期的NOW）
- ✅ 有"不做的事"（取舍才是Roadmap的价值）
- ✅ 资源约束是否合理（别让研发看了想哭）

## 常见问题

**Q：老板总是往Roadmap里加东西怎么办？**
→ 加可以，但要显性化：加这个意味着推哪个，让老板做选择，不是你来硬抗。

**Q：Roadmap要多久更新一次？**
→ NOW部分每个迭代确认一次，NEXT每月回顾，LATER每季度回顾。

**Q：对外（用户/合作方）的Roadmap怎么做？**
→ 只展示主题和方向，不承诺时间，永远保留"根据市场反馈调整"的空间。
