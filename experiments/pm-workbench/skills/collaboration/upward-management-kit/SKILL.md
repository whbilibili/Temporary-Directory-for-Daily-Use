# upward-management-kit

**向上管理沟通工具** — 让你的工作被看见，让资源和决策更顺畅。

## 触发条件

用户提到：向上管理、老板汇报、争取资源、推动决策、预期管理、跟高层沟通。

## 核心认知

向上管理不是"拍马屁"，是：
1. **让老板能做出好决策**（他们信息比你少）
2. **让自己的工作被正确评估**（做了不说等于没做）
3. **提前同步风险**（没有意外比什么都重要）

## 四大场景

### 场景一：日常汇报

**SCQA 结构（金字塔原理）：**
```
S（Situation）：背景/现状
C（Complication）：发生了什么变化/问题
Q（Question）：由此带来的核心问题是？
A（Answer）：我的建议/方案

示例：
S：上周搜索转化率正常，本周突然下跌8%
C：排查发现是X版本上线的排序算法调整导致
Q：是回滚还是继续观察修复？
A：建议紧急回滚，同时下周推出修复版本，理由：[3点]
```

**原则：**
- 结论先行（不要铺垫太久）
- 数据说话（不要只说感受）
- 提问题时带方案（不要只丢问题）

### 场景二：争取资源

**ROAD 框架：**
```
R（Result）：投入这个资源能带来什么结果？（量化）
O（Opportunity）：不投会错过什么？（机会成本）
A（Alternative）：如果不给全，最少需要什么？
D（Deadline）：最晚什么时候需要决定？

示例：
"我申请增加2名工程师用于搜索优化。
搜索QV提升30%预计带来X交易额，ROI约3倍（Result）。
现在是搜索基础建设窗口期，错过Q2很可能落后竞品6-12个月（Opportunity）。
如果只能给1人，我们优先做召回层，排序层Q3再做（Alternative）。
需要在本周五前决定，否则影响Q2排期（Deadline）。"
```

### 场景三：推动老板决策

```
决策推动四步：
1. 明确"这是需要你决策的事"（不要让老板以为你在汇报）
2. 列出选项+每项的利弊（不要只推一个选项）
3. 说明你的推荐 + 理由（让老板知道你的判断）
4. 说清楚"如果今天不决定，后果是什么"（给决策截止点）

模板：
"这件事需要您决策。
目前有两个选项：
A方案：[描述] 优点[…] 风险[…]
B方案：[描述] 优点[…] 风险[…]
我倾向A，因为[核心理由]。
如果本周没有决定，X时间节点会受影响。"
```

### 场景四：处理分歧

```
EARS 框架：
E（Express）：表达你的立场和理由
A（Acknowledge）：承认对方视角的合理性
R（Reframe）：用共同目标重新定义问题
S（Suggest）：提出化解分歧的方式

原则：
- 不要在会上正面对抗（提前私下沟通）
- 数据 > 观点（"我有数据支持"比"我觉得"有力）
- 找共同目标（"我们都希望X，只是路径不同"）
- 保留分歧的方式：小范围实验验证谁对
```

```
背景：
[2-3句必要背景，不超过这个]

现状 + 关键数据：
- [指标1]：[数值] [vs目标] [趋势]
- [指标2]：[数值] [vs目标] [趋势]

发现的问题/机会：
1. [最重要的]
2. [次重要的]

我的建议：
[选项A/B] → 推荐[A]，因为[1-2个核心理由]

需要的支持：[明确说出你需要什么]
时间节点：[决策/落地时间]
```

## 注意事项
- 老板时间有限：1分钟能说清楚，不要用10分钟
- 不要只报好消息：坏消息越早说越好，伴随解决方案
- 记录沟通共识：重要对齐发邮件/大象确认，避免"我以为"
