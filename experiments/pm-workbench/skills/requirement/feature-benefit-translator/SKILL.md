# Feature-Benefit Translator — 功能→用户利益翻译器

**核心原则：** 用户不关心你做了什么，他们只关心他们能得到什么。

## 功能 vs 利益 的区别

| 功能描述（PM视角） | 用户利益（用户视角） |
|---|---|
| "支持WebP格式" | "图片加载更快，不再等白屏" |
| "新增OCR识别" | "拍一张照片就能把纸质文件变成可编辑文字" |
| "引入端到端加密" | "你的对话只有你和对方能看到，连我们也看不到" |
| "优化了推荐算法" | "越用越懂你，减少翻找时间" |
| "上线AI助手功能" | "随时有个助手帮你，不用自己一个字一个字打" |

**FAB模型：** Feature（特性）→ Advantage（优势）→ Benefit（利益）

## 工作流程

### Step 1：接收功能描述

请用户提供：
1. 要翻译的功能描述（可以是一个或多个）
2. 目标用户是谁？（影响利益描述的语气和侧重点）
3. 用于什么场景？（版本更新说明/营销文案/产品说明书/PRD）

### Step 2：分析每个功能点

对每个功能，逐一思考：
1. **这个功能让用户能做什么（之前做不到的）？**
2. **这个功能让什么事情变得更容易/更快/更便宜？**
3. **这个功能消除了什么烦恼或恐惧？**
4. **这个功能带来了什么愉悦感或成就感？**

### Step 3：用5种风格翻译（根据场景选择）

**风格A — 版本更新说明**（简洁、直接、动词开头）
```
✨ 拍照识文字，纸质内容秒变可编辑
```

**风格B — 功能介绍页**（场景代入，有画面感）
```
开会时看到白板上密密麻麻的内容？
拍一张照，30秒变成你的会议笔记。
```

**风格C — 营销文案**（情感共鸣，突出变化）
```
以前拍完照，还要一个字一个字重新打。
现在不用了。
```

**风格D — 技术产品/B端**（强调效率提升，有数字）
```
文字识别准确率提升至99%，处理速度<0.5秒，
支持中英文混排，团队文档录入效率提升60%。
```

**风格E — App Store 简介**（简洁有力，突出价值）
```
OCR识别 — 拍照即可读取图片中的文字，告别手动输入
```

### Step 4：输出翻译结果

```
## 📝 功能→利益翻译结果

**目标用户：** [用户群体]
**使用场景：** [版本说明/营销/产品页等]

---

### 功能1：[原始功能描述]

**核心利益：** [一句话说清楚用户得到什么]

| 风格 | 翻译结果 |
|---|---|
| 版本更新说明 | [版本A] |
| 功能介绍页 | [版本B] |
| 营销文案 | [版本C] |
| B端/技术产品 | [版本D（如适用）] |

**推荐版本：** [根据用户的场景推荐哪个风格，说明原因]

---

[如有多个功能，依次输出]

### 整合版（如需要）

[把多个功能点整合成一段连贯的产品介绍文案]
```

### Step 5：质量检查

翻译后的文案需通过以下检查：
- [ ] 有没有技术术语（WebP/OCR/API...）？如果有，是否对目标用户必要？
- [ ] 能否想象一个真实用户看到这句话的反应：是"哦这跟我有关"还是"什么意思"？
- [ ] 动词是否用的是用户的动作（你可以做X）而不是产品的动作（我们提供了X）？
- [ ] 有没有承诺了无法兑现的效果？
