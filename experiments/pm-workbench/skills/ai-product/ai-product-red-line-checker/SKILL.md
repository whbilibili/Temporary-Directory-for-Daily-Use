# AI Product Red Line Checker — AI产品上线前红线检查清单

**AI产品的独特风险：** 与传统软件不同，AI的输出不可完全预测，一次线上事故可能被截图传播，造成品牌和监管双重危机。

## 上线前必查的6个维度（共42项）

### 第1维：幻觉与输出质量（10项）

- [ ] **1.1** 核心场景的AI输出准确率是否通过了人工评测？（准确率基准是多少？）
- [ ] **1.2** 是否测试了"边缘case"下的AI输出？（极端问题、非常规输入）
- [ ] **1.3** AI是否会自信地给出错误答案？（幻觉检测）
- [ ] **1.4** AI拒绝回答的情况下，是否有合适的降级提示？
- [ ] **1.5** AI输出是否会涉及虚假医疗、法律、财务建议？是否有免责声明？
- [ ] **1.6** 对于不确定的答案，AI是否会表达不确定性而非给出伪确定性结论？
- [ ] **1.7** 是否建立了用户反馈"AI回答有问题"的机制？
- [ ] **1.8** 对于关键决策场景，是否有"AI辅助但人工确认"的设计？
- [ ] **1.9** AI输出的内容是否可溯源（能找到依据）？
- [ ] **1.10** 是否有机制检测AI输出中的有害内容（歧视/暴力/违法）？

### 第2维：数据安全与隐私（8项）

- [ ] **2.1** 用户与AI的对话是否会被用于模型训练？是否告知并取得同意？
- [ ] **2.2** 是否有机制防止AI记忆/泄露用户的敏感信息到其他会话？
- [ ] **2.3** AI是否可能被诱导输出其他用户的数据？（提示词注入攻击）
- [ ] **2.4** 对于企业/B端用户，其数据是否与其他客户的训练数据隔离？
- [ ] **2.5** 是否符合所在地区的数据保护法规（GDPR/个保法/网安法）？
- [ ] **2.6** 敏感信息（身份证/银行卡/医疗）是否进入了AI的上下文？
- [ ] **2.7** 模型调用的API密钥是否安全存储，不会泄露给前端？
- [ ] **2.8** 是否有数据泄露的应急响应预案？

### 第3维：监管与合规（6项）

- [ ] **3.1** 是否满足「生成式人工智能服务管理暂行办法」的要求（中国大陆产品）？
- [ ] **3.2** AI生成内容是否需要显著标注？（国家要求AI生成内容需标识）
- [ ] **3.3** 是否有内容审核机制？（涉政/违法/不良内容的过滤）
- [ ] **3.4** 是否保存了必要的AI对话日志以满足监管要求？（日志留存期限）
- [ ] **3.5** 对于金融/医疗/教育等特定行业，是否满足行业监管要求？
- [ ] **3.6** 是否有针对未成年人的内容保护机制？

### 第4维：用户体验与信任（8项）

- [ ] **4.1** 用户是否知道自己在跟AI交互？（不能冒充真人）
- [ ] **4.2** AI是否可以被用户选择关闭/跳过？（强制使用AI会引发抵触）
- [ ] **4.3** AI的响应时间是否在用户可接受范围内？（>3秒需要有进度反馈）
- [ ] **4.4** 当AI系统故障时，是否有降级方案？（不能因AI挂了整个功能就挂了）
- [ ] **4.5** AI的个性/语气是否符合品牌调性？
- [ ] **4.6** 是否设计了"AI道歉"和"转人工"的流程？
- [ ] **4.7** 用户是否可以删除AI记忆/对话历史？
- [ ] **4.8** AI交互记录是否被用户投诉的客服能看到以便处理？

### 第5维：运营与监控（6项）

- [ ] **5.1** 是否有AI输出质量的实时监控指标？
- [ ] **5.2** 是否设置了异常报警（如：拒绝率突然升高、用户负反馈激增）？
- [ ] **5.3** 是否有快速回滚AI模型版本的能力？
- [ ] **5.4** 是否做了灰度发布？灰度期间的监控指标是什么？
- [ ] **5.5** 是否有"熔断"机制：AI错误率超过阈值时自动降级为非AI体验？
- [ ] **5.6** 是否考虑了AI服务成本急剧上升的风险（调用量爆炸）？

### 第6维：竞争与商业（4项）

- [ ] **6.1** AI功能依赖的第三方模型（OpenAI/Claude/Gemini等）服务协议是否允许商业使用？
- [ ] **6.2** 是否考虑了基础模型服务商突然停服/涨价的风险？
- [ ] **6.3** AI功能是否可能被竞对轻易复制？壁垒在哪？
- [ ] **6.4** AI功能的成本结构是否可持续？（以当前调用量算，毛利是正的吗？）
