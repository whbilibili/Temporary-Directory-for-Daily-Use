# Agent or Workflow Selector — AI产品架构决策工具

基于美团"王晓慧"AI销售员工的实践经验，帮你在 **Agent（端到端动态决策）** 和 **Workflow（固定流程）** 之间做出正确选择。

> 核心原则（来自王晓慧实践）：**销售场景用Agent追上限，客服场景用Workflow保稳定性**

## 核心区别

| 维度 | Workflow（固定流程） | Agent（动态决策） |
|---|---|---|
| **决策方式** | 预定义分支，人工穷举 | LLM动态推理，自主选择 |
| **适合场景** | 分支有限、流程标准化 | 分支多、决策树难维护 |
| **稳定性** | 高，输出可预期 | 较低，依赖模型能力 |
| **上限** | 有天花板（穷举完就到头了） | 更高（模型能力提升直接带来效果提升） |
| **风险** | 难以应对边缘情况 | 可能出现幻觉、不可控决策 |
| **典型产品** | 客服机器人、审核流程、标准化问答 | 销售对话、复杂任务规划、多步骤自主操作 |

## 工作流程

### Step 1：描述业务场景

请用户描述：
1. 这个AI功能要完成什么任务？
2. 面向的是C端用户还是B端用户/内部员工？
3. 任务的复杂度如何？会遇到哪些典型情况？

### Step 2：打分评估（5个维度）

对以下5个维度各打1-5分：

**① 决策分支数量**
- 1分：流程简单，分支 < 10个
- 3分：中等复杂，分支20~50个
- 5分：极度复杂，分支难以穷举（如销售对话：商家反对理由无数种）

**② 对稳定性的要求**
- 1分：必须100%可预期（如：资金审批、合规检查）
- 3分：允许一定偏差，有人工兜底
- 5分：稳定性要求低，追求效果上限（如：销售转化率）

**③ 任务的目标导向程度**
- 1分：完成步骤即可（过程重于结果）
- 3分：有明确目标，但路径灵活性低
- 5分：只关注最终结果，路径可以动态调整

**④ 场景的长尾异常比例**
- 1分：<5%的case会遇到预定义之外的情况
- 3分：10~30%会有预期外情况
- 5分：>50%的情况需要即兴应对

**⑤ 人工维护决策树的成本**
- 1分：流程稳定，维护成本低
- 3分：中等，每季度需要更新
- 5分：极高，业务规则每天都在变化

### Step 3：判断与建议

```
总分 = ①+②+③+④+⑤

5-10分  → ✅ 推荐 Workflow
11-17分 → ⚠️ 混合架构（核心流程用Workflow，边缘场景用Agent兜底）
18-25分 → ✅ 推荐 Agent
```

### Step 4：输出架构建议

```

**场景：** [用户描述的场景]

### 评分结果

| 维度 | 得分 | 说明 |
|---|---|---|
| 决策分支数量 | X/5 | ... |
| 稳定性要求 | X/5 | ... |
| 目标导向程度 | X/5 | ... |
| 长尾异常比例 | X/5 | ... |
| 维护成本 | X/5 | ... |
| **总分** | **XX/25** | |

### 推荐架构：[Workflow / 混合 / Agent]

**核心理由：** [2-3句话说明为什么]

### 具体实施建议

**如果选 Workflow：**
- 先穷举所有分支（建议用流程图可视化）
- 设计人工兜底节点（哪些情况转人工？）
- 定期审查流程覆盖率

**如果选 Agent：**
- 定义清晰的目标函数（追什么结果？）
- 设计 Human Takeover 机制（人工接管率作为核心指标）
- 从低风险场景切入（如：尾部客户、非核心任务）
- 建立分层评测体系（过程指标 + 结果指标）

**如果选混合架构：**
- 核心高频流程 → Workflow（稳定保底）
- 长尾复杂场景 → Agent（提升上限）
- 明确两者的切换条件

### ⚠️ 常见陷阱

[根据具体场景给出警告，例如：过度约束Agent会退化成Workflow]
```

### Step 5：延伸问题（可选）

如果用户已选定架构，可继续协助：
- **选了Agent**：帮助设计 Human Takeover Rate 指标体系
- **选了Workflow**：帮助识别最容易出现edge case的节点
- **需要验证**：推荐从哪个最小场景开始MVP验证
