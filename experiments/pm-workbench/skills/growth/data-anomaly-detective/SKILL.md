# data-anomaly-detective

**数据异动快速归因工具** — 系统化排查指标涨跌根因，10分钟内锁定方向。

## 触发条件

核心指标出现异常涨跌，用户说：数据跌了/涨了/异常/原因是什么。

## 核心原则：先排除噪声，再找根因

90%的"数据异动"有这几类来源：
1. **数据质量问题**（埋点/统计口径问题）
2. **外部因素**（节假日/大盘/竞品活动）
3. **产品变动**（上线了什么/下线了什么）
4. **真实业务变化**（需要深入分析）

## 排查框架（MECE）

### Step 1：确认异动真实性（5分钟）

```
检查清单：
□ 数据口径是否一致（日活 vs 周活 vs 月活？）
□ 统计时区是否正确
□ 是否有埋点丢失报警
□ 是否与其他平台数据交叉验证
□ 昨天/上周同期数据是否也有类似波动

→ 如果以上有异常：先修数据，不是业务问题
→ 如果数据准确：进入 Step 2
```

### Step 2：定位异动来源（下钻分析）

```
维度下钻顺序：
1. 时间：异动从什么时间点开始？
   → 对应哪个版本上线？哪个运营活动？

2. 渠道：哪个流量来源跌了？
   → 自然流量 / 付费 / Push / 社交

3. 用户群：哪批用户跌了？
   → 新用户 vs 老用户？
   → 特定设备/版本/地区？

4. 功能路径：哪个漏斗环节断了？
   → 曝光 → 点击 → 转化 → 完成，哪步跌了？

5. 内容/品类：哪个垂类受影响？
```

### Step 3：外部因素核查

```
□ 是否节假日/大促/特殊事件？
□ 竞品是否有大动作（发布/补贴/故障）？
□ 行业大盘是否整体下行？
□ 是否有负面舆情/媒体报道？
□ 是否有监管政策变化？
```

### Step 4：产品变动回溯

```
□ 近7天上线了什么功能/改版？
□ 有没有服务器故障/降级？
□ 有没有A/B实验影响了大盘？
□ 有没有运营活动到期结束？
□ Push/短信/邮件触达量是否有变化？
```

## 输出格式

```
【数据异动排查报告】

异动描述：[指标名] 在 [日期] 出现 [涨/跌 N%]

✅ 数据质量确认：[正常/发现问题：描述]

📊 下钻定位：
- 时间维度：[异动从X时间开始]
- 渠道维度：[X渠道贡献了N%的跌幅]
- 用户群维度：[X群体受影响最大]
- 漏斗维度：[X→Y环节跌了N%]

🔍 根因假设（按可能性排序）：
1. [最可能原因] — 证据：[数据支撑] — 验证方式：[如何确认]
2. [次要原因] — 证据：[…] — 验证方式：[…]
3. [待排查原因] — 需要：[还需要哪些数据]

⚡ 建议行动：
- 立即：[最高优先级动作]
- 今天：[需要确认的事项]
- 本周：[需要修复/优化的内容]

📅 下次复查时间：[具体时间点]
```

## 常见坑

| 坑 | 正确做法 |
|---|---|
| 上来就开会讨论原因 | 先用5分钟确认数据真实性 |
| 只看绝对值 | 同时看同比/环比 |
| 单一维度下钻 | 多维度交叉验证 |
| 找到一个原因就停 | 确认该原因能解释多少%的变化 |
| 忽略数据延迟 | 确认数据是否已完全同步 |
