# 日常临时目录

这是我的日常工作目录，用于存放灵感、临时探索、技术调研、工具脚本等各类内容。

---

## 目录结构

```
日常临时目录/
├── inbox/                      # 收件箱
├── notes/                      # 随手笔记
├── research/                   # 技术调研
│   └── harness-engineering/    # Harness 工程模板与文档
├── projects/                   # 小项目
│   ├── cursor-code-agent-hook/
│   ├── harness-engineering-example/

├── scripts/                    # 工具脚本
├── experiments/                # 实验验证
│   └── 产研流程技能组合包实验/
└── .meta/                      # 元信息
```

---

## 各目录说明

### 📥 inbox/
**新内容的第一落点。** 有任何想法、临时文件、还没想好放哪里的东西，先扔这里。不用纠结分类。建议每周清理一次，将内容归档到对应目录。

### 📝 notes/
**碎片化的文字记录。** 包括随手想法、问题记录、会议备忘、灵感片段等。不要求完整，想到就写。文件命名建议带日期，例如 `2026-04-17-想法.md`。

### 🔬 research/
**有一定深度的技术调研产出。** 包括技术选型分析、方案对比、论文阅读笔记、调研报告等。与 notes/ 的区别是：这里的内容经过整理，有结论和参考价值。

### 📦 projects/
**有一定规模的小项目。** 每个项目独立一个子目录，包含代码、配置、说明文档等。适合放有目录结构、多个文件的工程性内容。

### ⚙️ scripts/
**独立的工具脚本。** 单文件或少量文件的小工具，用完即走或长期复用都行。命名尽量见名知意，例如 `download_qwen.py`、`batch_rename.sh`。

### 🧪 experiments/
**想法原型和快速验证。** 专门用来放"不知道能不能成"的东西，允许凌乱、允许失败。每个实验建议单独建子目录，方便日后回溯或清理。

### 🗂 .meta/
**目录本身的元信息。** 包括经验教训（LEARNINGS.md）、操作记录等。一般不需要手动维护，由工具或 AI 助手更新。

---

## 使用习惯建议

**新内容进来** → 先放 `inbox/`，不纠结分类

**定期整理**（建议每周一次）→ 清理 `inbox/`，将内容移到对应目录

**写代码验证想法** → 放 `experiments/`，跑通后有价值再升级为 `projects/`

**写调研文档** → 碎片想法先放 `notes/`，整理成文后移到 `research/`

**写工具脚本** → 直接放 `scripts/`，单文件即可，不用建子目录
