LLM 运行机制

底层吞吐数据的基本原理——从 Token 到 Transformer，从自回归生成到显存带宽，完整拆解大语言模型每一次推理背后发生的事情。

1Token：模型看到的世界

LLM 不直接处理字符，也不处理单词，它处理的是 token。Token 是文本的基本计算单位，由分词器（tokenizer）切割产生。英文中，一个常见单词通常是 1 个 token；中文中，每个汉字通常对应 1–2 个 token。标点、空格、换行符也各自占用 token。

以 GPT-4 使用的 cl100k_base 词表为例，词表大小约为 10 万个 token。模型的每一次"输出"，本质上是从这 10 万个候选项中选出一个概率最高的。

为什么用 Token 而不用字符？

Token 在语义上更有意义，同时大幅压缩了序列长度，降低了计算量。一段 1000 字的中文，字符数约 1000，但 token 数通常在 600–800 之间。

2Transformer：处理序列的核心引擎

现代 LLM 几乎全部基于 Transformer 架构（2017 年由 Google 提出）。它的核心创新是自注意力机制（Self-Attention），解决了 RNN 无法并行、长距离依赖衰减的问题。

2.1 输入表示：从 Token 到向量

每个 token 首先被映射为一个高维向量，称为 embedding。GPT-4 的 embedding 维度约为 12,288。这个向量在训练中学习到了语义关系：king - man + woman ≈ queen 这类著名的向量运算，正是 embedding 空间的几何性质。同时，模型还会为每个 token 加上位置编码（Positional Encoding），因为 Transformer 本身不感知顺序，位置信息必须显式注入。

2.2 自注意力：让每个词"看见"其他词

自注意力的核心思想是：序列中的每个 token，都要与其他所有 token 计算相关性，然后加权聚合信息。每个 token 的 embedding 被线性变换为三个向量：

向量含义作用
Query (Q)我在问什么？发起注意力查询
Key (K)我能提供什么信息？被查询的索引
Value (V)我实际携带的内容加权聚合的内容
自注意力计算公式
Attention(Q, K, V) = softmax( QKᵀ / √d_k ) · V
除以 √d_k 是为了防止点积过大导致 softmax 梯度消失
直觉理解

假设句子是"猫坐在垫子上，它很舒适"。当模型处理"它"这个 token 时，自注意力会让"它"对"猫"产生高注意力权重，从而理解"它"指代的是猫。

2.3 多头注意力与前馈网络

多头注意力（Multi-Head Attention）将 embedding 分割为多个子空间，每个头独立计算注意力，最后拼接结果。GPT-3 有 96 个注意力头，每个头可以专注于不同的语言现象：句法依存、语义相似、指代关系、时态一致……

每个 Transformer 层在注意力之后，还有一个前馈网络（FFN），对每个 token 的表示独立做两层线性变换加激活函数（通常是 GELU）。研究表明，FFN 层是模型存储"事实知识"的主要场所——"巴黎是法国的首都"这类知识，大量编码在 FFN 的权重矩阵中。

3自回归生成：一次只输出一个 Token

LLM 的生成过程是自回归（Autoregressive）的：模型每次只预测一个 token，然后将这个 token 追加到输入序列，再预测下一个，如此循环，直到生成结束符或达到长度上限。

这个过程分为两个关键阶段：

阶段操作并行性特点
Prefill（预填充）并行处理所有输入 token，计算并缓存 KV完全并行速度快，计算密集
Decode（解码）逐个生成输出 token，追加 KV Cache串行吞吐瓶颈，带宽密集
KV Cache 的意义

如果没有 KV Cache，每生成一个新 token 都需要重新计算所有历史 token 的 K、V，计算量随序列长度平方增长 O(n²)。KV Cache 将已计算的结果缓存起来，使解码阶段降为 O(n)，代价是显存占用随序列长度线性增长。

4采样策略：如何从概率分布中选词

模型的最后一层输出一个 logit 向量（维度等于词表大小），经过 softmax 转换为概率分布。如何从这个分布中选出下一个 token，由采样策略决定：

Greedy Decoding
每次选概率最高的 token。确定性强，但容易陷入重复和平庸。
Temperature Sampling
将 logit 除以温度 T。T < 1 更保守，T > 1 更随机，T = 0 退化为贪心。
Top-k Sampling
只从概率最高的 k 个 token 中采样，屏蔽长尾低概率词。
Top-p (Nucleus) Sampling
动态选取累积概率达到 p 的最小 token 集合。比 Top-k 更自适应，是实践中的首选。
实践推荐配置
# 创造性写作 temperature = 0.8, top_p = 0.9 # 代码生成 / 精确任务 temperature = 0.2, top_p = 0.95 # 确定性输出 temperature = 0.0 # 等价于 greedy

5上下文窗口：模型的"工作记忆"

一个关键的误解

上下文窗口不等于"记忆"。每次对话都是独立的，模型不会记住上一次对话的内容，除非将历史对话显式地放入当前上下文。

6推理的硬件现实：显存与带宽

LLM 推理是显存带宽密集型任务，而非计算密集型。在解码阶段，GPU 的大部分时间花在从显存读取模型权重上，而不是做矩阵乘法。

优化手段原理效果
量化（INT8/INT4）将权重从 FP16 压缩到更低精度显存减半，带宽提升，速度 ×1.5–2
批处理（Batching）多请求打包并行处理GPU 利用率大幅提升
连续批处理动态合并不同长度请求吞吐量提升 5–10×
FlashAttention重写注意力计算的内存访问模式速度 ×2–4，显存减少
LLaMA-3 70B 推理估算（A100 80GB）
模型权重：~140 GB（FP16） A100 显存带宽：~2 TB/s 理论生成速度：~14 tokens/s（单卡） 量化到 INT4 后： 模型权重：~35 GB 理论生成速度：~56 tokens/s（单卡）

7训练与推理的本质区别

理解 LLM 还需要区分训练和推理两个阶段：

维度训练推理
参数状态持续更新（反向传播）完全固定
计算方向前向 + 反向传播仅前向传播
成本极高（GPT-4 估计 >$1亿）相对低廉
频率一次性（或定期微调）每次对话
知识更新通过数据更新不更新，有截止日期

模型的"知识"完全编码在训练后的参数中，推理时不会更新。这解释了为什么 LLM 有知识截止日期，以及为什么它有时会"幻觉"——它不是在查找事实，而是在根据训练数据的统计模式生成最可能的续写。

小结

LLM 的运行机制，本质上是一个在高维空间中做条件概率估计的数学系统。它没有理解，没有意图，没有记忆——它只是在极其精确地回答一个问题：给定这些 token，下一个最可能是什么？

但正是这个看似简单的问题，在足够大的模型、足够多的数据、足够深的层数之下，涌现出了令人惊叹的能力。理解这个底层机制，是使用和评估 LLM 的基础，也是避免对它产生错误期待的前提。
