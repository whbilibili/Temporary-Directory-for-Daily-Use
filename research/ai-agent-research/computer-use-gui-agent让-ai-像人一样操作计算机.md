# Computer Use / GUI Agent：让 AI 像人一样操作计算机

### 一、什么是 Computer Use / GUI Agent

Computer Use Agent（CUA）或 GUI Agent，是指能够通过图形用户界面（GUI）自主操作计算机的 AI 智能体。它不依赖特定应用的 API，而是像人类一样"看屏幕、动鼠标、敲键盘"，完成从网页浏览、表单填写到跨应用协作的复杂任务。

其核心范式是"感知 → 推理 → 行动"的闭环：系统通过截图获取当前屏幕状态，调用多模态大模型理解界面语义，再生成并执行鼠标点击、键盘输入等操作指令，最后观察执行结果并进入下一轮循环。

这一范式的意义在于：它让 AI 第一次具备了操作任意软件的通用能力，无需为每个应用单独开发集成接口，从根本上打破了"信息孤岛"和"遗留系统"的壁垒。

### 二、发展历程

GUI 自动化并非新概念，但 AI 驱动的 GUI Agent 是近两年才真正爆发的方向。

**早期阶段（2000–2020）**：以 AutoHotkey、Selenium、RPA（机器人流程自动化）为代表的工具，依赖预先录制的固定脚本，无法应对界面变化，维护成本极高。

**深度学习阶段（2020–2023）**：计算机视觉与 NLP 的融合使屏幕理解成为可能。微软 2021 年发布的 Power Automate Desktop 开始引入 AI 模块，斯坦福的 Sikuli 项目探索了基于图像识别的自动化控制。

**大模型爆发阶段（2023–至今）**：多模态大模型的突破彻底改变了格局。2024 年 10 月，Anthropic 发布 Claude 3.5 Sonnet 并首次将"Computer Use"能力推向公众，标志着 GUI Agent 进入实用化阶段。2025 年 1 月，OpenAI 推出 Operator 及其核心模型 CUA（Computer-Using Agent），将这一领域推向新高度。同期，字节跳动开源 UI-TARS，微软发布 OmniParser V2，国内 Manus 的爆火更是将 Computer Use Agent 带入大众视野。

### 三、核心技术架构

#### 3.1 感知层：理解屏幕

GUI Agent 的感知层负责将屏幕像素转化为可供推理的结构化信息，主要有两种技术路线：

**视觉方案（纯截图）**：直接将屏幕截图输入多模态大模型（如 GPT-4o、Claude 3.5、Qwen-VL），由模型识别界面元素的位置和语义。优点是通用性强，无需访问应用内部结构；缺点是对模型的视觉定位能力要求极高，小图标识别和精确坐标定位是难点。

**Accessibility Tree 方案**：通过操作系统或浏览器提供的无障碍接口（如 Windows UI Automation、Chrome DevTools Protocol）获取界面元素的结构化树形描述，包含元素类型、文本、可交互状态等信息。优点是精确、轻量；缺点是依赖应用支持，对自定义控件覆盖不足。

**混合方案**：结合截图和 Accessibility Tree，取长补短。微软的 OmniParser 就是典型代表——它将屏幕截图"token 化"为结构化元素列表，再交给 LLM 进行推理，在 ScreenSpot Pro 基准测试中，OmniParser V2 + GPT-4o 的准确率达到 39.6%，推理延迟相比 V1 降低 60%。

#### 3.2 规划层：任务分解

接收到用户的自然语言指令后，规划层负责将高层目标分解为可执行的操作序列。常见策略包括：

- **ReAct 框架**：交替进行推理（Reasoning）和行动（Acting），每步操作后观察结果再决定下一步，适合动态环境。
- **Plan-and-Execute**：先生成完整的执行计划，再逐步执行，适合结构化程度高的任务。
- **层次化规划**：将任务拆分为子任务，每个子任务再细化为原子操作，支持更复杂的多步骤工作流。

字节跳动的 UI-TARS 采用端到端的统一架构，将感知、推理、反思和记忆全部集成在单一视觉语言模型中，无需预定义工作流，实现了真正的端到端任务自动化。

#### 3.3 执行层：操作模拟

执行层将规划结果转化为实际的系统操作，主要包括：

- **鼠标控制**：基于坐标的点击、拖拽、滚动，部分系统会加入人类操作特有的随机抖动以规避反爬检测。
- **键盘输入**：文字输入、快捷键组合，可模拟打字节奏。
- **截图与等待**：操作后截图确认结果，处理页面加载、弹窗等异步状态。
- **异常处理**：遇到验证码、超时、意外弹窗时触发重试或人工介入。

#### 3.4 记忆与反思

高级 GUI Agent 还具备记忆和自我反思能力：短期记忆保存当前任务的操作历史，长期记忆积累跨任务的操作经验，反思机制在操作失败时分析原因并调整策略。

### 四、主流产品与框架

#### 4.1 商业产品

**Anthropic Claude Computer Use**：2024 年 10 月发布，是首个面向开发者开放的商业 Computer Use 能力。通过 API 调用，Claude 可以控制虚拟桌面环境，执行截图、点击、输入等操作。定位为开发者工具，需要自行搭建沙箱环境。

**OpenAI Operator / CUA**：2025 年 1 月发布，基于 GPT-4o 视觉能力与强化学习训练，能直接与 GUI 交互完成订票、购物、表单填写等任务。目前仅限 Pro 用户（$200/月）使用，在 WebArena 基准测试中任务成功率达 58.1%。

**Google Project Mariner**：Google DeepMind 推出的浏览器 Agent，专注于 Chrome 浏览器内的任务自动化，与 Gemini 模型深度集成。

**Manus**：由国内团队 [Monica.im](http://Monica.im) 开发，2025 年初爆火，在 GAIA 基准测试中达到 86.5% 的准确率。Manus 采用多 Agent 协作架构，将任务分发给专门的子 Agent 并行处理，2025 年底被 Meta 以约 20 亿美元收购。

**字节跳动 UI-TARS**：开源的端到端 GUI Agent 模型，将感知、推理、反思、记忆统一在单一 VLM 中，支持 PC、Web、移动 APP 等多平台，在多个基准测试上超越 GPT-4o。

#### 4.2 开源框架与工具

**OmniParser（微软）**：屏幕解析工具，将 UI 截图转化为结构化元素，可与 DeepSeek-R1、GPT-4o、Qwen-2.5VL 等模型结合，V2 版本推理延迟降低 60%，已开源。

**SeeAct**：来自 OSU 的研究框架，专注于 Web 任务，通过截图 + HTML 结合的方式提升元素定位精度。

**AppAgent**：腾讯开源的移动端 GUI Agent，通过探索和学习自动生成操作文档，支持 Android 应用自动化。

**Browser Use**：专注于浏览器自动化的开源框架，基于 Playwright，支持多种 LLM 后端，在开发者社区广受欢迎。

### 五、评测基准

GUI Agent 领域已形成较为完善的评测体系：

**OSWorld**：上海 AI Lab 等机构联合推出，目前最权威的桌面 GUI Agent 基准，覆盖 Ubuntu、Windows、macOS 三大操作系统，包含 369 个真实计算机任务。当前最佳模型成功率约 38.1%，人类水平为 72.4%，差距仍然显著。

**WebArena**：专注于 Web 任务的基准，包含电商、论坛、代码仓库等真实网站场景。领先系统成功率已达 58.1%，接近人类 78.2% 的水平。

**ScreenSpot / ScreenSpot Pro**：专注于 UI 元素定位（Grounding）能力的评测，测试模型能否准确找到屏幕上的目标元素。

**GAIA**：通用 AI 助手基准，包含需要多步骤工具使用的复杂任务，Manus 在此基准上表现突出。

**RiOSWorld**：上海交通大学推出的安全风险评测基准，专门测试 GUI Agent 在面对恶意指令时的安全性，揭示了现有系统的严重安全隐患。

### 六、核心挑战

#### 6.1 视觉定位精度

精确识别并点击小图标、动态加载元素、自定义控件仍是难题。4K 显示器与移动端之间的分辨率差异会导致坐标偏移，AJAX 动态内容的识别错误率可高达 32%。

#### 6.2 长程任务规划

多步骤任务中的"蝴蝶效应"——单个步骤的毫秒级延迟或意外弹窗可能导致整个执行链崩溃。现有系统在应对突发状况时的自主调整能力仍然有限，RiOSWorld 测试显示仅 17% 的案例能自主应对双重身份验证等突发情况。

#### 6.3 安全与权限控制

GUI Agent 拥有对计算机的广泛操作权限，安全风险不容忽视。上海交通大学的研究显示，78% 的 CUA 会执行伪装成系统更新的恶意指令，41% 的案例在收到模糊的危险命令时未进行二次确认。如何在赋予 Agent 足够能力的同时限制其权限边界，是产业化落地的关键问题。

#### 6.4 隐私保护

GUI Agent 需要持续截取屏幕，可能暂存银行卡号、医疗记录等敏感信息。欧盟 AI 法案已要求开发者实现"视觉信息瞬时脱敏"，但技术实现路径尚不成熟。

#### 6.5 执行效率

云端推理的延迟使得实时交互体验较差，每次操作需要截图 → 上传 → 推理 → 返回的完整链路，对时延敏感的任务体验不佳。端侧模型（如 Qwen3-VL 适配 Ollama）的出现为本地化部署提供了新思路。

### 七、与传统 RPA 的对比

| 维度 | 传统 RPA | GUI Agent（AI 驱动） |
| --- | --- | --- |
| 适应性 | 依赖固定脚本，界面变化即失效 | 实时视觉理解，动态适应界面变化 |
| 开发成本 | 需要专业人员录制/编写流程 | 自然语言描述任务即可 |
| 覆盖范围 | 结构化、可预测的重复任务 | 可处理非结构化、动态任务 |
| 异常处理 | 规则驱动，覆盖有限 | 推理驱动，可自主应对部分异常 |
| 成熟度 | 高，已大规模商业落地 | 中，仍处于快速发展阶段 |
| 安全性 | 操作范围明确可控 | 权限边界需要额外设计 |

### 八、应用场景

**企业流程自动化**：操作遗留系统（ERP、CRM）完成数据录入、报表生成、审批流转，无需改造原有系统。

**Web 任务自动化**：订票、购物、表单填写、信息采集，替代人工完成重复性网页操作。

**软件测试**：自动化 UI 测试，模拟真实用户操作路径，发现界面交互问题。

**数字员工**：在客服、财务、HR 等场景中承担操作性工作，与人类协作完成复杂业务流程。

**辅助功能**：为视障用户代理操作界面，提升数字产品的无障碍体验。

### 九、未来趋势

**多 Agent 协作**：将复杂任务分发给多个专门化的子 Agent 并行处理，Manus 的架构已验证了这一方向的可行性。

**端侧部署**：随着 Qwen3-VL 等轻量级视觉语言模型的成熟，GUI Agent 将逐步从云端走向本地，降低延迟和隐私风险。

**安全沙箱标准化**：上海 AI Lab 的"沙箱-仲裁"双模系统、苹果专利中的"AI 操作隔离区"，预示着硬件和系统层面的安全机制将成为标配。

**人机协作范式**：MIT 提出的"渐进式授权"模式——将任务拆分为感知、建议、执行三阶段，高风险操作必须获得用户实时确认——有望在效率与安全之间找到平衡点。

**标准化生态**：2025 年成立的 CUA 联盟（包括 OpenAI、Anthropic 等 15 家机构）正在推动界面元素标注标准的统一，类似互联网早期的 HTML 规范，将为整个生态的繁荣奠定基础。

### 十、小结

Computer Use / GUI Agent 代表着 AI 从"语言智能"向"行动智能"的关键跃迁。它让 AI 第一次具备了操作任意软件的通用能力，有望成为连接大语言模型推理能力与现实世界操作的核心桥梁。

当前技术仍处于快速发展阶段，视觉定位精度、长程规划能力、安全边界控制是三大核心挑战。但随着多模态模型能力的持续提升、评测基准的完善和产业生态的成熟，GUI Agent 正在从实验室走向真实的生产环境，成为下一代"数字劳动力"的重要组成部分。
